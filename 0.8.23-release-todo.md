## Merge to `main` and push to `origin/main` constraints

- Use a fresh, clean linked worktree and current `origin/main`; rebase or merge
  `origin/main` deliberately, resolve conflicts from the source of truth, and
  never force-push, delete, or rewrite `main`.
- Preserve `main`'s deletion of the stale Tegra design file while bringing the
  Jetson workflow route forward. The file is required later when the completed
  release branch itself is merged, not as a reason to resurrect stale content
  in the control-plane PR.
- The active repository ruleset requires a pull request, forbids non-fast-forward
  updates and deletion, and requires CodeQL with no error-level alerts or
  high-or-higher security alerts. A classic branch-protection endpoint is absent;
  this active ruleset is the authoritative GitHub constraint.
- The ruleset currently requires zero formal approvals, but release policy still
  requires independent code/evidence review, resolved material review findings,
  and a clean, candidate-bound provenance trail before merge.
- Before a merge PR is marked ready, pass the full local release gate from the
  candidate bytes: `cargo fmt --check`; `cargo clippy --workspace --all-targets
  -- -D warnings -A missing-docs`; `cargo check --workspace --all-targets`;
  `scripts/agent-verify.sh --tier=all`; `scripts/check.sh`; Actionlint; release
  state/view, board-currency, public-doc-truth, security/Gitleaks, shell, and
  unconfined strace gates. Resolve red results; do not use `--no-verify` or
  waive a baseline merely because it predates this branch.
- The dry-run control plane must be merged to `main` through its own reviewed
  PR before dispatch. Its manifest/baseline/provenance entries must authorize
  exactly one reviewed, open candidate PR and expire safely; dispatch must use
  `release.yml` from `main` and the exact candidate SHA.
- Do not push a `v*` tag, dispatch a non-dry release, publish, or use release
  credentials. A successful dry-run is evidence only and is not authorization
  for publication.
- After the reviewed PR merge, verify the merged SHA and all required GitHub
  checks on `origin/main`, update the single-writer release state and generated
  views to `main_integration: COMPLETE`, and push only the reviewed fast-forward
  branch reference with explicit HITL authorization.
