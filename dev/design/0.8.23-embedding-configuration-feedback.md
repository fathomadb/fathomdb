# 0.8.23 embedding-configuration feedback

## Problem

A body-bearing graph edge creates embedding work. When the caller has no
usable embedder, the current retry ladder can surface only an opaque
`SchedulerError` from `drain()` after backoff. That makes a caller
configuration error look like a scheduler fault and gives no corrective action.

## Decision

0.8.23 defines a typed embedding-configuration outcome for this condition. It
must be observable through the affected Rust, Python, and TypeScript public
surfaces, identify the operation that requires an embedder, and name the two
remediations: configure a usable/default embedder or submit graph data that
does not request body embedding. The outcome occurs before retry backoff; it
does not silently enqueue impossible work.

## Scope and acceptance

- Slice 10 first characterizes body-less and body-bearing graph edges with and
  without a live embedder, including two sequential stores in one process.
- A live-embedder reproduction remains a reliability blocker and takes its own
  RED/GREEN remediation slice before packaging.
- The no-embedder condition receives a red-first regression test proving an
  immediate typed, remediation-bearing outcome rather than a generic delayed
  drain timeout.
- Any exported error or lifecycle-surface change updates the Rust, Python, and
  TypeScript interface documents in the implementation commit.

## Non-goals

This does not make embedding automatic, select CUDA, change CPU defaults, or
mask genuine worker failures. A configured embedder that cannot complete work
remains an operational error with its own diagnostics.
