# 0.8.23 Gitleaks guardrails design

## Decision

0.8.23 adds Gitleaks at two boundaries: a redacted scan of the staged index in
the tracked pre-commit hook, and an always-on, redacted full-history scan in
GitHub Actions. Neither scan substitutes for review or permits credentials to
be printed into logs.

## Requirements

- Pin the scanner version and make bootstrap install it reproducibly.
- The pre-commit hook scans the staged index, not unstaged working-tree data.
- CI scans reachable history independently of path filters, so a docs-only
  change cannot bypass it.
- Fail closed when the scanner is unavailable or finds a secret; redact output.
- Regression tests prove the hook and CI wiring, including a synthetic staged
  credential that fails without exposing its value.

## Non-goals

- This slice does not rewrite history, rotate credentials, or change release
  publication authority.
- It does not introduce a third-party collector or alter the release workflow's
  finalization semantics.
