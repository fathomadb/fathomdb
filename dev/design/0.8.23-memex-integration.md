# 0.8.23 Memex integration feedback and graph-projection contract

## Problem

Memex found that a body-bearing semantic edge needs an embedder to complete
`edge_fact` projection, while its own graph-only retrieval setting disabled the
default embedder along with vector candidates. The resulting retry-driven drain
timeout does not identify the configuration problem. A body-less edge avoids
that pending projection work, but its graph-expansion semantics are not yet a
documented substitute for the body-bearing relation. Other observations require
public-SDK characterization before they can be assigned to either integration
configuration or FathomDB runtime reliability.

Memex also needs a query policy that distinguishes the three independent
concerns: embedding availability for body-bearing projection, vector candidates
in retrieval, and graph expansion. The current public `search` surface exposes
the graph arm but not a documented vector-arm control, so it does not establish
whether graph-on/vector-off is supported.

## Decision

FathomDB retains accepted deferred writes for compatibility. It adds a typed,
non-retryable `FDB_EMBEDDER_REQUIRED` outcome when `drain()` can prove that
pending embedding work cannot advance in the current session, rather than
spending retry backoff and returning a generic scheduler timeout.

Each supported SDK also receives an additive embedding-readiness report. The
report returns `ready`, `processing`, `deferred`, or `blocked`; usable-embedder
availability; pending count and affected kinds; and, when blocked, the same
code, operation, state, remediations, and stable documentation URL as the
typed outcome. Rust owns the domain payload; PyO3 and N-API preserve it without
string parsing.

Structured lifecycle diagnostics may expose the same code and bounded counters,
but tracing is supplemental. A caller must be able to receive and act on this
feedback without enabling a trace subscriber. Diagnostics and reports must not
include edge body text.

## Integration boundary

Embedder availability and whether a consumer includes vector candidates in its
ranking are independent capabilities. For Memex's graph witness, FathomDB must
run with a usable embedder for body-bearing edge projection; Memex may suppress
vector candidates in its own retrieval/ranking policy. FathomDB neither turns
vector ranking on automatically nor adopts a Memex ranking policy.

Slice 10 will characterize direct public-SDK structural-edge traversal. The
result becomes documented contract: either structural edges support the relevant
graph expansion, or body-bearing projected edges are the supported relation for
that route. The test may not infer a product promise from a single consumer
fixture.

Slice 10 must also close the graph-on/vector-off query policy. It will either
prove an existing public shape in Rust, Python, and TypeScript; add a closed,
typed arm-selection/query-options surface that keeps `explain` arm counts
truthful; or document and validate that graph expansion intentionally requires
vector candidates. A fused result is not proof of any of these contracts.

## Reliability boundary

The sequential-edge, sequential-store, and child-process findings are evaluated
with fresh owned-synthetic public-SDK controls. A live-embedder drain failure or
reproducible abnormal parent-process exit is a FathomDB release blocker and
creates a separate RED/GREEN remediation slice. A no-embedder blocked outcome
is expected configuration feedback, not a scheduler-regression disposition.

## Acceptance and interfaces

- Rust exposes a public matchable domain outcome and readiness report; Python
  and TypeScript expose equivalent typed fields and stable `FDB_EMBEDDER_REQUIRED`.
- The operation identifies `graph_edge_body_projection` or the relevant vector
  projection, and remediation offers a usable/default embedder, a caller
  embedder, or deliberately non-embedding input where valid.
- Public interface documents and consumer guidance explain the body-bearing
  graph edge rule, readiness handling, and the independent retrieval-candidate
  decision.
- The public query contract explicitly disposes graph-on/vector-off and tests
  the selected behavior, including zero vector-hit evidence if it is supported.
- Regression tests cover the full Memex findings matrix and preserve the initial
  RED failure evidence before implementation reaches GREEN.

## Non-goals

This does not automatically download a model, enable CUDA, select a ranking
policy, promise structural-edge traversal before it is characterized, or mask
actual scheduler/worker failures as configuration errors.
