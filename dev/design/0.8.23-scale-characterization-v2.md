# 0.8.23 scale-characterization v2

## Authority and replacement

This is the executable successor to the v1 protocol and aggregator contract.
V1 remains historical pre-registration only: it has no output artifact or
measurement. V2 uses protocol `0.8.23-scale-characterization-v2` and artifact
`schema_version: 2`; no coexistence, fallback, or v1 artifact acceptance is
permitted for a future run.

## Exact root, documents, and nonzero execution

For candidate full SHA `H`, `SCALE_OUTPUT_DIR` must be exactly
`dev/plans/runs/0.8.23-scale-H-raw`. A successful complete matrix has exactly
62 regular non-symlink files: `provenance.json`, `matrix-manifest.json`, and
the 30 canonical `ac013-N-T-repR.log` files with their 30 basename-only SHA-256
sidecars. No directory, extra, absolute path, `*` marker, duplicate, or missing
entry is valid. The V2 schema defines the root input as `kind: complete`, with
`regular_file_count: 62`, and embeds the parsed `matrix-manifest.json`.

The runner creates a **partial root** before the first child and writes
`partial-manifest.json` after every child attempt. A nonzero child exit ends the
matrix immediately; it must not create `matrix-manifest.json`, sidecars for
unrun repetitions, or a complete root. Its partial manifest records every
attempted `(rows, treatment, repetition)` in order, the final nonzero child
exit, the final raw-log basename/digest, and every unrun tuple. It may retain
sidecars only for attempted logs. The runner then emits only the output artifact
with `ENVIRONMENT_INVALID`, the captured nonzero exit and raw-log digest, and
null summary. It retains the partial root for diagnosis but it is not a v2
complete-matrix input and cannot be aggregated as `INSUFFICIENT_SAMPLES`.

`INSUFFICIENT_SAMPLES` is reserved for a separately explicit
`--partial-retained` command, whose root contains all executed logs/sidecars,
`partial-manifest.json` with `execution_mode: partial_retained`, and no
`matrix-manifest.json`; its output names every intentionally unrun repetition.
It preserves every valid completed repetition in a partial artifact matrix:
one to six cells, each with one to five completed repetitions. It may never be
`CHARACTERIZED`, has a null summary, and must name the omitted tuples. A
missing capture before timing is
`MISSING_PREREQUISITE`; no root is created. No timing attempt is `DEFERRED`.

## Structural schema and semantic validator

`0.8.23-scale-artifact-v2.schema.json` is the sole structural schema for a V2
output, `provenance.json`, `matrix-manifest.json`, `partial-manifest.json`, and
the parsed treatment records. It replaces V1 for future execution. A V1 file
may be retained only as history and is never an alternate V2 input.

The complete manifest has exactly 30 entries. Every entry has rows, treatment,
repetition, basename-only log and sidecar, raw SHA-256, zero child exit, and a
typed parsed treatment record. The schema makes cold one numeric latency and
one numeric result count, and warm 1,000 of each. It also requires every setup
duration, accepted write count, observed vector-row count, drain outcome, and
all four zero query counters. An `INSUFFICIENT_SAMPLES` partial matrix retains
one to six cells with one to five valid completed repetitions each; semantic
validation requires at least one omitted tuple or cell with fewer than five.
Only `CHARACTERIZED` has exactly six cells and five repetitions per cell. Each
repetition retains its raw identity, child exit, record, and within-repetition
statistics. Cold statistics are exactly min/max/mean. Warm statistics are
exactly min/max/mean/p50/p95/p99. A characterization summary contains only six
five-repetition cells with treatment-appropriate repetition-level
median/minimum/maximum ranges.

JSON Schema cannot prove cross-object equality or a complete Cartesian product.
The V2 validator must therefore reject, before status derivation, any manifest
or artifact for which any of these semantic checks fail:

1. the 30 manifest tuples are exactly `10000|100000|1000000` ×
   `process_cold|warm` × `1..5`, each once, with filenames matching their tuple;
2. the 62-file closure contains only the two named JSON files and exactly those
   30 log/sidecar pairs, every sidecar has a basename-only target, and
   `sha256sum -c` matches the recorded digest;
3. candidate SHA agrees among root, manifest, provenance, and artifact; each
   record's `n`, treatment, accepted writes, and observed rows agree with its
   tuple, and the record grammar has exactly one ordered line with no unknown
   key;
4. a characterized matrix and summary have the same complete six-cell
   Cartesian product, every cell has repetitions `1..5` exactly once, and no
   sample is pooled across repetitions; a partial-retained matrix instead has
   only valid completed tuples and explicitly names every omitted tuple; and
5. a partial root has no complete manifest, its attempted tuples are an ordered
   prefix of that Cartesian order, `failed_child` has exactly one final nonzero
   child, and `partial_retained` names every omitted tuple explicitly.

The validator derives `CHARACTERIZED` only after both schema and all five
semantic checks pass, complete provenance is present, all integrity arrays are
empty, and the complete input has been validated. It rejects an asserted status
that differs from the derived status. A partial, malformed, dirty, corrupt, or
otherwise invalid root never reaches summary calculation.

`ENVIRONMENT_INVALID` may describe either a `failed_child` partial root or a
62-file complete root that validation subsequently found dirty, corrupt, or
contradictory. Its summary is always null. The nonzero-child mutation must use
the former representation; it must not relabel that partial root as complete.

For warm repetitions, 1,000 retained query samples require min/max/mean/p50/
p95/p99 in both the per-repetition record and its summary cell. Cold has one
first-query sample and therefore permits only min/max/mean at both levels; it
must not invent percentiles. Missing a required warm percentile is malformed
evidence and derives `ENVIRONMENT_INVALID`, never a partial characterization.

## V2 record and provenance contract

Each sole ordered `AC013_TREATMENT_RECORD` has all keys in
`0.8.23-scale-artifact-v2.schema.json` exactly once. Warm retains 1,000 numeric
samples and 1,000 numeric result counts; cold retains one of each. The real
Engine::search path emits explicit `query_errors`, `query_timeouts`,
`query_skips`, and `query_invariant_failures`; the matrix manifest captures the
actual child `command_exit_status`. Zeros are valid only as captured values.
`embedding_ms=not_separately_observable` is the sole nonnumeric
`CHARACTERIZED` field; GPU `not_present_or_unavailable` remains provenance.
Every other unavailable required capture produces `MISSING_PREREQUISITE`. An
incomplete provenance object must name the unavailable top-level evidence path
and a nonempty reason; it cannot insert `null`, zero, or `unknown` into a
complete-provenance field. `CHARACTERIZED` requires the schema's complete
provenance object, so this honest unavailable form can never be upgraded into a
characterization.

`provenance.json` is mandatory and schema-valid before timing: candidate; exact
0.8.22 Slice5 release-state/blob/evidence digest and measured lock stack;
lock/build/built-process SQLite; fixture; host/GPU; and isolation/load/process
facts. `matrix-manifest.json` is sealed only after every child exit is zero and
all 30 sidecars verify. The aggregator validates the schema first, then the
digest, file, source/Git, record, and cardinality semantics; only then derives
status and non-pooled summaries.

## Required RED validation suite

The first implementation commit must add failing tests named
`test_scale_ac013_v2_schema.sh` and `test_scale_ac013_v2_validator.py` (or
equivalent tests at the runner and validator seams) for every row below. They
are a test-only synthetic fixture and must not write a release result artifact
or claim a measurement.

| RED mutation | Required failing assertion |
| --- | --- |
| V1 artifact or protocol | V2 loader rejects it; there is no fallback. |
| Missing/extra/reordered/absolute root path | Complete closure is rejected. |
| Missing, tampered, or foreign sidecar | `sha256sum -c` and recorded digest reject it. |
| Tuple duplicate, omission, or extra | 3 × 2 × 5 exact Cartesian validation rejects it. |
| Warm 999/1001 samples or result counts | Typed record validation rejects it. |
| Cold not exactly one sample/result count | Typed record validation rejects it. |
| Duplicate/unknown/malformed record key | Record grammar rejects it. |
| Nonzero query counter, drain invariant, or child exit | Derived status is `ENVIRONMENT_INVALID`; summary is null. |
| Nonzero child partial root | It cannot be represented as complete or as `INSUFFICIENT_SAMPLES`. |
| Partial-retained 1–4 repetitions | It derives `INSUFFICIENT_SAMPLES`, preserves those valid repetitions, has no complete manifest or summary, and names each unrun tuple. |
| Partial artifact asserted as 6 × 5 | It is rejected: only a `kind: complete` root may assert the complete `CHARACTERIZED` matrix. |
| Warm repetition or summary missing p50/p95/p99 | Typed statistics reject it as malformed; cold still accepts exactly min/max/mean. |
| Missing provenance capture | It derives `MISSING_PREREQUISITE` with explicit unavailable fields. |
| Dirty candidate, Slice5 mismatch, lock-stack mismatch | Derived status is `ENVIRONMENT_INVALID`. |
| Partial, corrupt, or malformed input asserted `CHARACTERIZED` | Validator rejects the artifact before summary calculation. |
| Valid synthetic six-cell fixture | Non-pooled five-repetition summaries validate; it is test data, not a scale claim. |

No runner code, measurement, or output artifact is authorized by this design.
