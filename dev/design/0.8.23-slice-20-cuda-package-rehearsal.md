# Slice 20 — CUDA package rehearsal

## Scope

After Slice 10 closes, Slice 20 builds the actual Linux x86_64 Python wheel and
Linux x64 N-API platform tarball with `embed-cuda`. It also builds and attests
the thin npm main tarball as the consumer package paired with that platform
tarball; the thin tarball itself does not contain CUDA code. All other package
lanes remain CPU-only. It retains a non-publishing rehearsal bundle; it does
not create a tag, upload a registry artifact, promote a dist-tag, or create a
release.

## Design

A dedicated read-only `cuda-package-rehearsal` trusted-runner job starts only
after it verifies an immutable lowercase 40-hex candidate SHA, the same-run
Slice 10 route receipt, and the canonical Slice 10 preflight-witness digest.
It replaces only the final Linux x64 Python/N-API producers. The existing
non-Linux-x64 Python and N-API CPU lanes remain unchanged; the output artifact
names consumed by the publisher remain unchanged. `all-builds-passed` must need
the rehearsal job before a future publication path can advance.

This Slice 20 implementation and rehearsal are dry-run-only. It cannot make a
tag or non-dry-run path consume the unmerged-SHA exception; any later canonical
tag package-build route needs separately reviewed authorization and design.

The job emits one canonical `cuda-package-rehearsal/v1` manifest with exact
inventory equality: the Python wheel, thin npm main tarball, Linux x64 N-API
platform tarball, candidate SHA, build-input identity, canonical preflight
witness digest, and an individual SHA-256 digest for every package and smoke
evidence file. It verifies all bytes before upload and rejects a missing,
extra, substituted, or symlinked member.

Both Python and npm GPU smokes run in network-isolated GPU containers from only
the retained package bytes. The CPU-default smokes likewise use network-isolated
driverless containers; no source import or host-only npm GPU execution is valid
evidence.

Implementation is deliberately deferred until Slice 10 closure. It will add
`scripts/release/cuda-package-rehearsal.sh`, a schema and fail-closed verifier,
and a dedicated verifier test; update `.github/workflows/release.yml`,
`scripts/check-cuda-release-contract.py`,
`scripts/tests/test_cuda_release_contract.sh`, and `scripts/agent-test.sh`.

## Requirements

**R20-1 — trusted input.** Rehearsal accepts only the exact candidate SHA with
a verified Slice 10 route receipt and preflight witness.

**R20-2 — final-package bytes.** The three Linux x64 consumer artifacts are
retained under their existing publisher artifact names and package topology. The
wheel and Linux x64 N-API platform tarball are built with `embed-cuda`, without
`rerank-cuda`; the thin npm main tarball is built and attested as their paired
consumer package, not misrepresented as containing CUDA code.

**R20-3 — rehearsal manifest.** A strict canonical
`cuda-package-rehearsal/v1` manifest binds candidate SHA, preflight witness
digest, build-input identity, package filenames/SHA-256s, and smoke evidence
digests. It rejects unknown fields, duplicate names, missing files, symlinks,
noncanonical bytes, and altered artifacts.

**R20-4 — installed-artifact smokes.** Python and npm consumers install only
the retained rehearsal bytes. Driverless CPU-default smokes use network-isolated
containers with no GPU nodes and an `env -i` allowlist; they complete
open/embed/write/search/close/exit.

**R20-5 — GPU engagement.** Network-isolated GPU container smokes retain package
digest, selected GPU UUID, host index, device name/driver, requested in-process
ordinal, smoke PID, matching `nvidia-smi` row, and process result. Missing UUID/
PID/device correlation or CPU fallback fails.

**R20-6 — graph and publication boundary.** The read-only CUDA package job
depends on Slice 10 route/witness verification and becomes a required aggregate
predecessor. It cannot publish, tag, use registry credentials, or alter a
dist-tag. Before any later publisher stages or publishes a retained artifact,
it downloads the rehearsal manifest and invokes the fail-closed verifier against
the exact wheel and npm tarballs; unverified or substituted bytes are rejected.

## Acceptance criteria

- RED→GREEN mutations reject CPU-feature substitution, CUDA reranker inclusion,
  duplicate Linux-x64 producers, renamed publisher artifacts, and a missing
  aggregate dependency.
- Manifest tests reject cross-candidate preflight, byte substitution, incomplete
  smoke evidence, noncanonical JSON, and symlinked inputs.
- Smoke tests reject source imports, host-only npm GPU execution, network/GPU
  visibility in CPU containers, and GPU evidence without UUID/PID correlation.
- Tests reject a missing or invalid Slice 10 receipt/witness, broad job
  permissions, registry credentials, tag creation, and artifact-byte changes
  after manifest generation.
- Workflow mutations reject a publisher that stages or publishes a wheel or npm
  tarball without first verifying the downloaded rehearsal manifest and exact
  bytes. This test does not authorize a tag or publication execution.
- One authorized dry-run independently reviews the complete rehearsal bundle;
  static tests do not substitute for it.
