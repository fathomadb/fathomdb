# Slice 20 — CUDA package rehearsal

## Scope

Slice 20 locally implements the **candidate dry-run rehearsal** for the Linux
x86_64 Python wheel and Linux x64 N-API platform tarball with `embed-cuda`. It
also builds and attests the thin npm main tarball as the paired consumer
package; the thin tarball itself does not contain CUDA code. The candidate
bundle additionally contains one versioned Linux x86_64 `fathomdb` CLI archive:
its coordinate records the release version, target triple, archive filename,
and exact SHA-256 digest. All non-Linux-x64 ordinary package rows remain
CPU-only. A real trusted-runner rehearsal begins only after a valid Slice 10
route receipt and candidate-bound, schema-valid preflight witness exist. The
route retains a non-publishing rehearsal bundle; it does not create a tag,
upload a registry artifact, promote a dist-tag, or create a release.

The candidate route is not a canonical tag producer. It must never turn a
candidate rehearsal byte into a tag/non-dry-run publisher input, and it does
not establish that a CPU Linux x64 build is publishable.

## Design

A dedicated read-only `cuda-package-rehearsal` trusted-runner job starts only
after it verifies an immutable lowercase 40-hex candidate SHA, the same-run
Slice 10 route receipt, and the candidate-bound, schema-valid Slice 10
preflight witness. `cuda-contract-preflight` builds the candidate package bytes
while producing that witness; `cuda-package-rehearsal` verifies those retained
bytes, runs installed-artifact smokes, and seals the rehearsal bundle. Together
those two candidate-only jobs are the sole candidate rehearsal producer for the
Linux x64 wheel/N-API/CLI bytes. Local
RED→GREEN implementation and static mutation tests may proceed while those
external inputs are unavailable; they cannot produce a rehearsal result or
close the slice. Existing non-Linux-x64 Python and N-API CPU lanes remain
unchanged.

This Slice 20 implementation and rehearsal are dry-run-only. The dedicated
read-only `canonical-cuda-package-route-required` gate runs for every tag or
non-dry-run dispatch before the aggregate and every publisher. Until the future
canonical route is separately commissioned, it exits nonzero with a clear
"canonical CUDA package route required" error. It receives no candidate input,
candidate route receipt, candidate preflight witness, candidate artifact,
OIDC/registry/release credential, secret, or secret-derived capability. Its
failure is required upstream of `all-builds-passed` and every publisher; nothing
downstream may be skipped into success.

The future canonical Linux x64 package route is a separate owned work item, not
an implicit promotion of either candidate job. It requires all of the following
before implementation or enablement:

- a named owner and separately reviewed canonical-route design;
- canonical tag provenance that never consumes the unmerged-SHA exception;
- a canonical build and retained installed-artifact evidence bundle, distinct
  from candidate rehearsal output; and
- an independently reviewed decision describing its publisher inputs and
  exact verification edge.

Until those prerequisites pass, `all-builds-passed` and every downstream
publisher must fail closed for canonical Linux x64 publication rather than
falling back to an unproven CPU producer or promoting candidate bytes.

The CLI addition is a manifest-shape change, not a permissive optional member.
The rehearsal job therefore emits one canonical `cuda-package-rehearsal/v2`
manifest; the verifier rejects a `/v1` or an unversioned manifest. The strict manifest/verifier topology
has exact inventory equality: the Python wheel, thin
npm main tarball, Linux x64 N-API platform tarball, versioned Linux x86_64 CLI
archive, candidate SHA, build-input identity, candidate-bound schema-valid
Slice 10 preflight-witness digest, and an individual SHA-256 digest for every
package and smoke evidence file. It verifies all bytes before upload and rejects
a missing, extra, substituted, duplicate, or symlinked member. The verifier
checks the archive coordinate and CLI archive SHA-256 digest before extracting
the archive; each CLI evidence record cites that same retained digest.

Python, npm, and CLI consumers install or extract only the retained rehearsal
bytes. Driverless unset/`auto` smokes use network-isolated containers. The CLI
driverless unset/`auto` CPU smoke runs the extracted archive's `fathomdb` binary
with `FATHOMDB_EMBED_DEVICE` absent, no GPU nodes, and no source-tree executable;
it must report/select typed CPU and complete its open/embed/write/search/close/
exit exercise. The CLI compatible-GPU `auto` smoke runs that exact archive on a
compatible GPU and retains the selected UUID/PID correlation; CPU fallback
fails. Two CLI forced `cuda:N` unavailable/incompatible smokes retain their classified
typed failures: one has CUDA unavailable and one has a visible but
incompatible device/probe. Neither may become a CPU success. No source import,
host-only npm GPU execution, or host-built CLI is valid evidence.

Implementation proceeds under HITL `seq:249`, which separates Slice 10's
external release gate from local slice work. It adds
`scripts/release/cuda-package-rehearsal.sh`, a schema and fail-closed verifier,
and a dedicated verifier test; updates `.github/workflows/release.yml`,
`scripts/check-cuda-release-contract.py`,
`scripts/tests/test_cuda_release_contract.sh`, and `scripts/agent-test.sh`.

## Requirements

**R20-1 — trusted input.** A real rehearsal accepts only the exact candidate
SHA with a verified Slice 10 route receipt and candidate-bound, schema-valid
preflight witness. Their absence permits local static implementation and test
work only; it fails a rehearsal attempt without creating a success artifact.

**R20-2 — candidate rehearsal bytes.** The four Linux x64 consumer artifacts
are retained as candidate rehearsal bytes under their existing package topology:
the Python wheel, thin npm main tarball, Linux x64 N-API platform tarball, and
one versioned Linux x86_64 `fathomdb` CLI archive. The wheel, N-API platform
tarball, and CLI archive are built with the same `embed-cuda` feature tuple,
without `rerank-cuda`; the thin npm main tarball is built and attested as their
paired consumer package, not misrepresented as containing CUDA code. The CLI
archive coordinate and its SHA-256 bind the executable bytes that are installed
for every CLI smoke. These are not canonical publication artifacts and cannot
be promoted or republished by a tag/non-dry-run route.

**R20-3 — rehearsal manifest and verifier.** A strict canonical
`cuda-package-rehearsal/v2` manifest binds candidate SHA, preflight witness
digest, build-input identity, exact package coordinates/SHA-256s (including the
versioned Linux x86_64 CLI archive), and smoke evidence digests. The v2 verifier
accepts exactly that four-artifact inventory and the required Python/npm/CLI
evidence inventory; it rejects `/v1`, unknown fields, duplicate names, missing
files, symlinks, noncanonical bytes, and altered artifacts. A sealer invokes
this verifier before upload and a future consumer verifies the same topology;
no route may reinterpret the candidate bundle as a canonical package input.

**R20-4 — installed-artifact smokes.** Python, npm, and CLI consumers install
or extract only the retained rehearsal bytes. Driverless unset/`auto` smokes use
network-isolated containers with no GPU nodes and an `env -i` allowlist.

The `env -i` allowlist leaves `FATHOMDB_EMBED_DEVICE` absent, so the CUDA-capable artifact proves
unset/`auto` resolves to typed CPU; the smokes complete
open/embed/write/search/close/exit. The CLI driverless unset/`auto` CPU smoke
must run the retained archive binary, not a source-tree or host-built binary.

**R20-5 — GPU engagement.** Network-isolated GPU container smokes retain package
digest, selected GPU UUID, host index, device name/driver, requested in-process
ordinal, smoke PID, matching `nvidia-smi` row, and process result. Missing UUID/
PID/device correlation or CPU fallback fails. The CLI compatible-GPU `auto`
smoke uses the retained CLI archive digest and has the same PID/UUID proof.

**R20-5a — forced CUDA fail-closed.** The bundle retains a CLI forced `cuda:N`
unavailable/incompatible smoke for both unavailable CUDA and a visible but
incompatible initialization/probe outcome. Each records the requested ordinal,
classified typed failure, exact CLI archive digest, and absence of an effective
CPU selection. An exit 0, a CPU report, or a substituted CLI byte is failure.

**R20-6 — two-route graph and publication boundary.**
`cuda-contract-preflight` builds candidate bytes and emits the candidate-bound
Slice 10 witness; `cuda-package-rehearsal` verifies, smokes, and seals those
bytes. Neither job can publish, tag, use registry credentials, alter a dist-tag,
or create a canonical publisher input. `canonical-cuda-package-route-required`
runs on each tag/non-dry-run route with read-only contents permission only, no
candidate input/artifact/receipt/witness, and no OIDC, registry, release, or
secret capability; it exits nonzero until the separate canonical route is
reviewed and enabled. It is a required upstream dependency of the aggregate and
every publisher. A later canonical route must independently verify its own
retained manifest and exact wheel/npm/CLI archive bytes; it must reject
candidate bundles and any unverified or substituted bytes. This is a
candidate-only and no-publication boundary: Slice 20 neither designs nor
implements a canonical publisher route.

## Acceptance criteria

- RED→GREEN mutations reject CPU-feature substitution, CUDA reranker inclusion,
  a missing/version-mismatched CLI archive, a changed CLI archive digest,
  duplicate candidate Linux-x64 rehearsal producers, a restored ordinary CPU
  Linux-x64 producer, and a missing candidate-rehearsal aggregate dependency.
- RED→GREEN workflow mutations reject a removed, softened, or skipped
  `canonical-cuda-package-route-required` gate on a tag/non-dry-run route; they
  also reject every canonical publisher consuming candidate rehearsal output,
  including an artifact with a canonical publisher name.
- Manifest/verifier tests reject cross-candidate preflight, `/v1` topology,
  missing/extra CLI archive members, CLI archive byte substitution, incomplete
  Python/npm/CLI smoke evidence, noncanonical JSON, and symlinked inputs.
- Smoke tests reject source imports, host-only npm GPU execution, a source-tree
  or host-built CLI, network/GPU visibility in CPU containers, GPU evidence
  without UUID/PID correlation, and unavailable/incompatible forced-`cuda:N`
  CLI paths that return CPU success instead of their typed failure.
- Tests reject a missing or invalid Slice 10 receipt/witness, broad job
  permissions, registry credentials, tag creation, and artifact-byte changes
  after manifest generation.
- Workflow mutations reject a canonical publisher that receives candidate
  rehearsal bytes, a registry/release credential, a secret, or an artifact
  before the separately owned canonical route is reviewed and enabled. This
  test does not authorize a tag or publication execution.
- One authorized dry-run independently reviews the complete rehearsal bundle;
  static tests do not substitute for it.
