# Slice 70 — offline TDD plan

## Implementation boundary

Create a feature-gated `fathomdb-tc5-benchmark` workspace package plus the
narrow `fathomdb-engine` benchmark module. The facade, ordinary CLI, Python,
and TypeScript surfaces remain unchanged. The existing global vector-stage test
toggle and hybrid `TOP_K_BIT_CANDIDATES` remain ordinary-search behavior and are
not reused.

## Committed RED-to-GREEN order

1. Strict spec/manifest parsing: unknown and duplicate fields, range/pin/digest
   failures before open, canonical length-prefixed SHA-256 bytes, and `proptest`
   codec round trips.
2. Injected device policy: no visible CUDA→CPU; one pinned UUID→logical
   `cuda:0`; ambiguous, failed, non-CUDA, or attestation drift→typed failure;
   cache-only asset-unavailable before open with no downloader path.
3. Safe result/output contract: identities/timings/cardinality/result digests,
   no raw content/paths/IDs/predictions, create-new nonsymlink output, atomic
   write and failure injection.
4. Real SQLite deterministic fixture: request-scoped `ReaderRequest::VectorStage`,
   runner K/top-k propagation, immutable scope applied to candidate/rerank/truth,
   same snapshot, candidate order distinct from exact ground truth, and drift
   failure.
5. Route observer: a positive VectorStage/Candidate/ExactRerank/GroundTruth
   trace and exact absence of Search, FTS compile/query, fusion, graph, and CE.
6. Required-feature binary boundary: strict two-path CLI, no algorithm/device
   environment override, ordinary-build compile failure, benchmark build success,
   and Rust interface update.

## Deferred external evidence

Only after Slice 20 package/rehearsal evidence: installed CUDA binary startup,
real CUDA UUID/PCI/name/driver attestation, selected-device engagement, and the
safe deterministic GPU smoke. A real TC-5 GPU run remains contract-invalid until
the external TC-5 execution contract is amended; no characterization is implied.
