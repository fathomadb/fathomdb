# Slice 70 — offline TDD plan

## Implementation boundary

Create a feature-gated `fathomdb-tc5-benchmark` workspace package plus the
narrow `fathomdb-engine` benchmark module. Before that private work resumes,
Slice 70 adds the reviewed public dual-runtime policy, OpenReport/binding
propagation, `doctor gpu`, and Linux x86_64 CLI artifact/rehearsal contract.
The existing global vector-stage test toggle and hybrid `TOP_K_BIT_CANDIDATES`
remain ordinary-search behavior and are not reused.

## Completion path and RED-to-GREEN order

Slice 70 closes only after each product prerequisite is reviewed, integrated,
and locally verified in the following order. The external CUDA evidence from
Slices 10 and 20 remains `PENDING_EXTERNAL`; it does not prevent these local
increments, but it prevents a release or supported-artifact claim.

1. Product embedding policy and report: strict `auto`/`cpu`/`cuda:N` parsing,
   provider resolution, engine propagation, and Rust/Python/TypeScript
   requested/effective/reason report mapping. Forced CUDA never falls back to
   CPU; `auto` records an honest CPU reason. This increment is in reviewed
   integration.
2. Production device resolution: RED injected inventory/probe tests for empty
   visibility, one visible UUID with incompatible initialization, one selected
   UUID, forced ordinal mapping, and driver-query failure; then Green the
   CUDA-driver enumeration, UUID inventory/report propagation, and minimal
   mapped-device probe. Deterministic fixture providers cover unavailable and
   visible-incompatible records; real trusted-runner GPU evidence is observed,
   not manufactured by those fixtures.
3. Product diagnostic/configuration: RED a fixture-provider matrix for every
   `doctor gpu [--json]` outcome before Green CLI wiring: policy-satisfied auto
   CPU fallbacks -> `0`; auto driver or allocation/provider probe failure ->
   `probe_failed`, typed CPU effective device, exit `70`; forced `cuda:N`
   not-compiled/unavailable/incompatible -> no effective device, exit `65`;
   forced driver or allocation/provider probe failure -> no effective device,
   exit `70`; and invalid policy -> `70` without provider access. The RED
   tests must prove `DoctorGpuDiagnosticResult` maps raw probe evidence rather
   than serializing normal `DeviceResolution`, so
   `CudaProbeError::ProbeFailed` cannot be policy-satisfied in the diagnostic.
   Pin the ordered visible UUID inventory and selected UUID/visible-ordinal
   binding, as well as no database open, engine initialization, model
   loader/download, or configuration write. The CUDA operation is a minimal
   allocation/provider probe with no model. The repository has no `init` root
   today; this work does not create `init`, a configuration-writing command, or
   an SDK device setter unless a reviewed public-interface decision explicitly
   commissions one.
4. Slice 10 witness v2 migration: RED deterministic fixtures for exact
   unavailable and visible-incompatible forced `cuda:0` records, their retained
   stdout/stderr filename/hash/root-digest bindings, v1 refusal,
   cache-manifest substitution, CPU-effective mutation, and the read-only HF
   seed plus fresh writable XDG product-cache topology; then Green the
   schema/verifier. This is evidence-contract work only, not a runner dispatch.
5. Deterministic Linux CLI archive and candidate rehearsal: RED static and
   verifier fixtures for `fathomdb-cli` `embed-cuda` forwarding, the exact
   target/filename/layout, archive digest, POSIX PAX `atime`/`ctime` deletion,
   fixed absolute extracted leaf argv, extraction permissions, and the four
   diagnostic-only CLI doctor evidence records; then Green the archive,
   sealer, and verifier contract. Python and N-API—not CLI—retain the installed
   model-operation proof.
6. Private TC-5 work resumes only after Steps 1–5 are complete. Its committed
   RED-to-GREEN sequence is:

   1. Strict spec/manifest parsing and invocation: exactly `--spec` and `--result`,
      no benchmark-control environment variables, unknown and duplicate fields,
      range/pin/digest failures before open and with no result file, canonical
      length-prefixed SHA-256 bytes, and `proptest` codec round trips.
   2. Injected benchmark device policy: no visible CUDA→CPU; one pinned UUID→logical
      `cuda:0`; ambiguous, failed, non-CUDA, or attestation drift→typed failure;
      cache-only asset-unavailable before open with no downloader path.
   3. Safe result/output/status contract: identities/timings/cardinality/result
      digests, no raw content/paths/IDs/predictions, malformed-input no-output,
      typed non-measurement device/asset outcome, create-new nonsymlink output,
      and race-safe non-replacing finalization with failure injection.
   4. Real SQLite deterministic fixture: request-scoped `ReaderRequest::VectorStage`,
      runner K/top-k propagation, immutable scope/count/selection digest applied
      to candidate/rerank/truth in one deferred snapshot, deterministic
      distance-plus-row-key ties, candidate order distinct from exact ground truth,
      and drift failure.
   5. Route observer and timing attribution: a positive
      VectorStage/Candidate/ExactRerank/GroundTruth trace and exact absence of
      Search, FTS compile/query, fusion, graph, and CE. Assert candidate and rerank
      are separately timed CPU SQLite stages and ground-truth timing is separate or
      explicitly excluded.
   6. Required-feature binary boundary: strict two-path CLI, no algorithm/device
      environment override, ordinary-build compile failure, benchmark build success,
      and Rust interface update.

No workflow, release helper, or verifier implementation belongs to this
design-only step. Their later RED→GREEN implementation follows the accepted v2
contract and remains candidate-only with no publication.

## Deferred external evidence

Only after Slice 20 package/rehearsal evidence: installed CUDA binary startup,
real CUDA UUID/PCI/name/driver attestation, selected-device engagement, and the
safe deterministic GPU smoke. A real TC-5 GPU run remains contract-invalid until
the external TC-5 execution contract is amended; no characterization is implied.
