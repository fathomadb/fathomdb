# Slice 10 — unmerged candidate provenance route

## Decision

HITL authorized an equivalent provenance route for one unmerged release commit.
It is not a `release/*` exception. A `main`-owned, independently reviewed,
time-bounded manifest authorizes one exact SHA for a non-publishing CUDA
preflight. No candidate code executes before the hosted verifier accepts that
manifest and corroborates its review facts.

## Requirements

**R10P-1 — main-owned control plane.** A separately reviewed PR first lands a
strict schema, verifier, and workflow control plane on `main`. It contains no
candidate entry and checks out `github.workflow_sha`, never the candidate.

**R10P-2 — exact authorization.** A later provenance-only `main` PR may add one
record with schema version, lowercase 40-hex candidate SHA, candidate PR and
head SHA, independent required reviewers, UTC expiry, and the sole purpose
`0.8.23 non-publishing CUDA preflight`. Unknown fields, duplicate SHA, expiry,
or a nonmatching input fail closed.

**R10P-3 — independent review corroboration.** The hosted verifier reads GitHub
only after strict manifest validation. It requires the PR to be open, non-draft,
same-repository, targeted at `main`, and still headed by the authorized SHA.
Each named reviewer must have a latest submitted `APPROVED` review of that exact
commit and differ from the PR author. API, pagination, or shape failure is
failure.

**R10P-4 — route receipt.** The hosted verifier retains a safe receipt with
workflow ref/SHA, run ID/attempt, manifest digest, candidate SHA, PR/review IDs,
and digests of read-only API responses. It never retains credentials or corpus
content.

**R10P-5 — candidate execution boundary.** Every dry-run candidate-executing
job, including `verify-release`, package builds, and CUDA preflight, needs the
hosted gate. The self-hosted job first verifies the same-run receipt, then checks
out exactly the authorized SHA. Tags and non-dry-run publication remain on the
canonical route and cannot use this exception.

## Acceptance criteria

- RED→GREEN tests reject absent, duplicate, malformed, expired, or mismatched
  authorization records; noncanonical bytes; and unsafe receipt paths.
- Workflow mutation tests reject candidate checkout or candidate script/action
  execution in the hosted verifier, missing hosted dependencies, workflow-ref/
  SHA substitution, and a tag/non-dry-run exception path.
- GitHub API fixture tests reject foreign, draft, retargeted, changed-head, or
  self-approved PRs; stale approval; change request; and API pagination/error.
- External closure evidence retains runner-group 3 and selected-repository raw
  responses, `main` protection/ruleset evidence, dispatch-principal policy,
  provenance-PR review evidence, route receipt, and the real Slice 10 witness.

## External configuration boundary

The runner group must remain selected-repository and restricted to the exact
`fathomadb/fathomdb/.github/workflows/release.yml@refs/heads/main` workflow.
The route additionally needs a reviewed dispatch-principal policy or protected
environment approval with no self-approval. GitHub configuration is evidence to
capture, not a fact inferred from repository YAML.
