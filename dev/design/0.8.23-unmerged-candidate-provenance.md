# Slice 10 — unmerged candidate provenance route

## Decision

HITL authorized an equivalent provenance route for one unmerged release commit.
It is not a `release/*` exception. A `main`-owned, independently reviewed,
time-bounded manifest authorizes one exact SHA for a non-publishing CUDA
preflight. No candidate code executes before the hosted verifier accepts that
manifest and corroborates its review facts.

## Requirements

**R10P-1 — main-owned control plane.** A separately reviewed PR first lands a
strict schema, verifier, and workflow control plane on `main`. It contains no
candidate entry and checks out `github.workflow_sha`, never the candidate.
The verifier fails closed unless the current, independently reviewed protection
baseline attestation establishes the `main` protection/ruleset and runner-group
restriction without a bypass route. The attestation has a bounded expiry and
binds retained raw configuration-response digests; repository YAML cannot
substitute for it.

**R10P-2 — exact authorization.** A later provenance-only `main` PR may add one
record with schema version, lowercase 40-hex candidate SHA, candidate PR and
head SHA, independent required reviewers, UTC expiry, and the sole purpose
`0.8.23 non-publishing CUDA preflight`. Unknown fields, duplicate SHA, expiry,
or a nonmatching input fail closed. The record names the separately reviewed,
merged `main` provenance-PR number, its exact independently reviewed
`provenance_head_sha`, and its exact merged-main `provenance_commit`. The head
and merge commit are distinct fields and are not assumed equal. Its independent
review must approve the exact reviewed head; merge evidence must bind the exact
merged commit. Both are required authorization inputs, not retrospective
documentation.

The checked-in candidate manifest is either an empty control-plane manifest or
contains exactly one valid, unexpired `0.8.23` authorization record. Multiple
records, including multiple active records, fail closed. A schema-valid record
may be introduced only by the separately reviewed provenance-only `main` PR;
the static contract must accept that future valid state without accepting an
unreviewed current record.

**R10P-3 — independent review corroboration.** The hosted verifier reads GitHub
only after strict manifest validation. It requires the PR to be open, non-draft,
same-repository, targeted at `main`, and still headed by the authorized SHA.
Each named reviewer must have a latest submitted `APPROVED` review of that exact
commit and differ from the PR author. For the separately merged provenance PR,
the named reviewer approval must bind `provenance_head_sha`, while its merged
state and `provenance_commit` are verified independently. Equal-timestamp
reviews for one reviewer are ambiguous and fail closed. API, pagination, or
shape failure is failure.

**R10P-4 — route receipt.** The hosted verifier retains a safe receipt with
workflow ref/SHA, run ID/attempt, manifest digest, candidate SHA, PR/review IDs,
and digests of read-only API responses. It never retains credentials or corpus
content. Before any candidate checkout, each self-hosted consumer compares its
current run ID and attempt, workflow ref and SHA, manifest digest, and requested
candidate SHA exactly to the receipt; a stale or cross-run receipt fails. The
receipt verifier takes the current main-owned candidate-manifest path, strictly
parses it, rejects noncanonical bytes, computes its canonical SHA-256, and
requires that digest to equal the receipt before candidate checkout.

**R10P-5 — candidate execution boundary.** Every dry-run candidate-executing
job, including `verify-release`, package builds, and CUDA preflight, needs the
hosted gate. The self-hosted job first verifies the same-run receipt, then checks
out exactly the authorized SHA. Tags and non-dry-run publication remain on the
canonical route and cannot use this exception.

**R10P-6 — dispatch authority.** The self-hosted candidate-executing job uses
the named protected environment `cuda-unmerged-preflight`. Its reviewed GitHub
configuration requires an independent approver, prohibits self-approval, and
does not permit an administrator bypass. The workflow must declare that exact
environment; its removal, substitution, or comment-only lookalike fails the
structural static contract check.

## Acceptance criteria

- RED→GREEN tests reject absent, duplicate, malformed, expired, or mismatched
  authorization records; noncanonical bytes; and unsafe receipt paths.
- Workflow mutation tests reject candidate checkout or candidate script/action
  execution in the hosted verifier, missing hosted dependencies, workflow-ref/
  SHA substitution, missing/substituted/comment-only protected environment, and
  a tag/non-dry-run exception path.
- GitHub API fixture tests reject foreign, draft, retargeted, changed-head, or
  self-approved PRs; stale approval; change request; and API pagination/error.
  They cover the normal case in which a reviewed provenance head and its
  squash/rebase merged-main commit differ.
- Receipt tests reject a stale run/attempt, different workflow ref/SHA, manifest
  digest, canonical-manifest mismatch, or candidate SHA before any candidate
  checkout.
- Manifest tests accept only the empty control-plane form or one complete valid
  record and reject two records, an expired record, or a noncanonical manifest.
- External closure evidence retains runner-group 3 and selected-repository raw
  responses, unbypassable `main` protection/ruleset and protected-environment
  evidence, provenance-PR review/merge evidence, route receipt, and the real
  Slice 10 witness.

## External configuration boundary

The runner group must remain selected-repository and restricted to the exact
`fathomadb/fathomdb/.github/workflows/release.yml@refs/heads/main` workflow.
The route requires the named `cuda-unmerged-preflight` protected environment
with independent approval, no self-approval, and no administrator bypass. The
reviewed protection-baseline attestation is an execution prerequisite, not
merely closure evidence. GitHub configuration is never inferred from repository
YAML.
