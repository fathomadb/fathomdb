# 0.8.23 local Windows development environment

## Purpose

`gh-runner-wonl-win11` is the local, native Windows development and validation
environment for controlled reproduction, builds, and tests. It is a persistent
Windows 11 Pro x64 guest on this Linux host, managed through system libvirt on
KVM/QEMU. It is not a generally available GitHub Actions runner.

## Authorized access

- The guest is reachable only from the host's libvirt NAT network. Its DHCP
  address must be discovered for each session through the system-libvirt lease
  query; no address is a stable contract.
- Authorized operators use the dedicated `runner` account over SSH with the
  host-held dedicated credentials and pinned host verification. Credentials,
  key locations, and guest addresses are not stored in this repository.
- Interactive access uses `virt-manager` against system libvirt. The SPICE
  display is host-loopback-only. The QEMU guest agent is available for
  host/guest management.
- Only users authorized for system libvirt and the dedicated credentials may
  operate the guest. Do not expose guest SSH outside host NAT or distribute the
  credentials without a separate security design.

## Repository execution model

1. Stage a source archive from the host over authenticated SSH/SCP.
2. Extract to a unique guest-local NTFS directory below `C:\ci\`.
3. Install locked dependencies and run Windows-native build/test commands
   through PowerShell or Git Bash.
4. Copy artifacts and logs back to the host, then remove only that run's guest
   staging directory.

Do not use network shares, WSL-mounted source paths, or persistent repository
checkouts under `C:\projects\`. Guest-local NTFS is required so tests exercise
Windows locking, path, process, and filesystem behavior.

## Capability and boundary

The guest provides Git for Windows, Git Bash, uv, Python 3.11, and QEMU guest
tools. It is a manually invoked local validation host. Registering it as a
GitHub Actions self-hosted runner requires explicit authorization, a dedicated
service/account, repository-scoped registration, and restrictive labels.
