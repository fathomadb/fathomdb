# P1 — real-schema temporal ledger

Status: initial semantic witnesses pass; scoped prototype, not production integration.

The actual Engine creates format-35 storage and performs canonical writes.
`poc_fragments` stores fragment identity, exact canonical revision cursor, source,
valid interval and committed knowledge interval. Original assertion bytes remain
in canonical storage. Splits reference the original immutable revision; the
single current canonical head is never multiplied. Actual intrinsic revision and
source IDs come from `_fathomdb_artifact_revisions` / `_fathomdb_source_links`;
shipped evidence issues/resolves that exact revision and source. It has no field
for candidate fragment identity: a new temporal evidence carrier needs a successor.

TEMP intent and exact claim/body/source binding live only on the actual writer
connection, with `temp_store=MEMORY`. Canonical insert and fragment transformation
are one transaction; a fragment insertion fault rolls back both. Staging itself
is a separate transaction: failure explicitly rolls it back, and close/crash
removes connection-local intent. This prototype requires exclusive adapter
mutation while staging; direct concurrent Engine writes, including an identical
payload, are prohibited. Payload equality is not an operation nonce. Production
needs in-writer operation binding to remove that restriction.

Only one governed node temporal write per operation is supported. Known cuts are
recorded single-write commits, plus empty cut zero. Ordinary batch-interior row
cursors are rejected. Arbitrary temporal batches need a governing batch commit
identity and are not implemented. Existing ordinary/anonymous reads keep their
shipped meanings. Candidate corrected-time selection deliberately resolves ledger
fragments despite canonical supersession; this is a new explicit operation,
not a reinterpretation of existing ReadView flags. Current source authority is
strict even for prior belief. Existing engine flag combinations are tested
separately without changing them.

Real G11 writes from two sources with the same endpoints/relation leave two
canonical edge revisions but only one current head. Simultaneous independent
source claims therefore cannot be mapped to ordinary current edge heads under
this ADR. This is an observed successor boundary, not a bypassed constraint.
Temporal edge operations are not implemented by this node-ledger candidate.

Tests cover partial A/B/A, nested withdrawal without revival, late/future changes,
half-open V/K, source identity, actual deletion/erase, exact intrinsic evidence,
head uniqueness, G11, shared-transaction faults and actual reopen/rebuild.
Sixteen property cases compare all V/K selections to last explicit covering
assertion before and after reopen/rebuild. New claim/source identity metadata is
removed with its last owned fragment. No pre-feature knowledge is invented.

The scoped adapter rejects independent canonical owner validity fields: its ledger owns the valid-time window. Declared derived revisions require positive source-link proof; an absent link fails closed.
