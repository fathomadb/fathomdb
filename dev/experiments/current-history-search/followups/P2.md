# P2 candidate and qualification boundary

The candidate uses the actual Engine writer/schema and eight independent real
SQLite read-only (`query_only=ON`) worker connections. It is a standalone SCOUT;
it is not installed in `Engine::search`, the canonical AC-076/081 fixture, or
bindings. Current output uses native BM25, cursor tie ordering and body dedup;
it does not claim the Engine's hybrid fusion/RRF scores.

Each reader starts one transaction and point-reads the candidate certificate and
actual visibility generation together. The certificate owns a half-open resolved
valid-time interval and scope. A healthy request proceeds directly to MATCH;
it does not visit writer admission or enumerate canonical IDs/history/vocabulary.
Metadata VM steps and ranking VM steps are measured separately. Tests require
identical work with fixed current bodies and 0/4/16 prior versions, and verify
both metadata accesses use integer-primary-key lookups.

An invalid reader rolls back/releases its transaction before waiting for writer
admission. Publication rechecks compatibility after acquiring admission. An older
resolved V cannot roll publication backward; it receives `BackwardTime` unless
an already-pinned compatible snapshot can finish. Future rows are recorded in an
indexed boundary frontier, including initial installation over a populated store.
A visibility change conservatively reconciles current heads through a partial
index plus all previously indexed rowids. Clock-only refresh processes crossed
frontier entries and their dependencies. Authority is reevaluated before publish;
source expiry, revocation and nonterminal closure cannot authorize stale success.

Refresh cost is **not** history-independent: frontier entries and source-link
expansion can include historical revisions. Ordinary writes incur conservative
current-head reconciliation; no incremental-repair performance claim is made.
Only the healthy certified read has the measured excluded-history independence.

Requests have a five-second experiment queue/admission/response budget (overridable
in focused tests), three refresh attempts, and bounded worker channels. These are
experimental controls, not proposed production defaults. The budget bounds queue
and admission waiting; an already executing writer publication runs to completion.
A timed-out receiver does not cancel owned reader work. `close` stops admission,
drains/joins workers, and closes the Engine; active SQL can extend close time.

The T-012 scout copies the canonical generator, seeds, body sizes, query sequence
and full discarded warmup. It uses governed logical IDs so real supersession can
create H0/4/16; canonical T-012 uses anonymous records. Therefore its 1,000-sample
native end-to-end distributions can inform feasibility but cannot pass AC-076.
AC-081a/b remain NOT TESTED through an integrated candidate. Distinct real reader
progress is demonstrated as a candidate witness, not a shipping AC-081c verdict.
Boundary-burst refresh is measured separately without hiding it in warmup.


Fresh candidate fixtures now enable FTS secure-delete before population and remove
current rows synchronously in canonical deletion transactions. The focused
rollback, raw-shadow, survivor and pinned-WAL retry witness passes; older candidate
files are not upgraded or retroactively qualified. The ordinary shipping node-FTS
residual-term diagnostic is separate and still fails. See [results](RESULTS.md).
P2 does not consume P1 temporal fragments; healthy-read isolation does not prove
world-time selection across partial/future corrections or write-heavy latency.
