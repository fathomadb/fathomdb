# P3 selected native corpus experiment

The backend is per-call contentless native FTS5, with `detail=full`,
`columnsize=1` and production `porter unicode61 remove_diacritics 2` tokenization.
It uses the production safe query compiler, including stopword/literal fallback.
Ordinary native FTS is the numerical/order reference; the old vocabulary-scanning
custom scorer is not a measured candidate. There is no custom-scoring speed claim.

`history::search` requires a held main `Transaction`. It streams selected UTF-8
scalars into one private in-memory connection and a separate eligibility table,
inside one prepared-insert transaction. Zero-token rows and all property names
contribute statistics. Output eligibility applies before ranking/limit; winner
bodies hydrate from the same held main snapshot. Body dedup and cursor ties are
explicit. The private connection has `temp_store=MEMORY` before schema creation;
it stores no full-text content table and no durable/shared cache. This still
allocates postings, doc lengths, metadata, allocator capacity and winner bodies.
No memory/swap zeroization guarantee is claimed.

Both success and error drop private state on return. The caller owns the main
transaction. A dropped response receiver does not cancel active work; tests show
an owned snapshot still blocks complete WAL erasure, then releases for retry.
The experiment's external reader can finish after `Engine::close` because it is
not part of the shipping Engine reader pool. The cell driver joins all worker
threads before exiting. This is a measured ownership boundary, not a claim of
integrated production cancellation/close behavior.

## Real fixtures and selectors

Fresh actual Engine databases retain the existing canonical head/G11 constraints.
Governed Engine writes create each prior version. Node fixtures have 10,000 node
owners; edge fixtures have 10,000 edge owners plus 10,001 explicit endpoint nodes;
property fixtures have 10,000 node owners and two scalar names (20,000 documents).
The remaining property-body field is fixed. Each indexed scalar is exactly 128 or
4,096 UTF-8 bytes. H is 0/4/16 prior versions per owner. Node/property fixtures mark
one percent of owners pending in every revision; edges have no analogous node
state overlay. Counts report this distinction rather than calling 9,900 active
nodes 10,000 active nodes.

The completed fixture imports explicit temporal fragments from **actual batch
receipt high-water cuts**, never row-cursor-interior pseudo-commits. This import
is fixture setup after canonical writes; it is not a production atomic temporal
batch protocol (P1 records that limitation). Every earlier assertion spans V[0,100).
At the latest cut, ten claims change only V[20,100), retaining the preceding
revision's V[0,20) fragment. Other claims receive a full-window correction.
H0 has no preceding correction. K bounds are half-open actual commit cuts.

- Current: V30/latest K, current active artifact policy.
- Corrected: V10/latest K, including the retained preceding fragments.
- Prior: V10/the actual final receipt of the H/2 round.
- Archive: all body-bearing canonical revisions admitted by current authority.
- Inactive: current canonical heads with inactive state admitted.
- Superseded: all active canonical revisions.
- Both: inactive and superseded revisions admitted.

Current source authority and nonterminal dependency-closure checks apply to every
selected document before it contributes statistics. Small real governed-source
and source-bucket-closure witnesses verify denial, exact evidence revision
ownership, and absence from the private statistical corpus. The large fixtures
use legacy source ownership; they measure selector execution cost but are not a
large governed dependency fanout benchmark. Full production temporal/evidence
routing still requires the successor/API decisions from P1.

## Predeclared campaign controls

Order is H → bytes → callers → view → family, with family innermost: 252 cells.
Each schedules exactly 1,000 requests, with no replacement after refusal/error.
The controller enforces 600 seconds/cell, 7,200 seconds/campaign, and samples the
whole child process RSS every 50 ms, stopping at 8 GiB. RSS includes fixture
construction, actual Engine internals and private corpora; it is not isolated
corpus allocation. Sampling can overshoot. Indexed UTF-8 byte counts are recorded
separately. Fixture construction/selection/ranking/hydration/drop are charged;
fixtures are reused by later cells for the same family/H/payload, as recorded by
cell order. An interrupted fixture lacks a completion marker and is refused,
never silently reused. All unfinished/not-run cells remain in the report.

Only 1,000 successful requests and no termination qualify p50/p99. Quantiles use
the canonical nearest-rank `ceil(N*p)-1` definition. Raw logs and process stderr
remain in `/tmp/current-history-followups-results/p3`; `campaign.json` records all
252 outcomes, including process-level exits and unfinished scheduled work.
Budgets are experiment controls, not validated production limits or new SLOs.
