## Minimal proposed alignment

Retain A/S/Q/P/O/R/U/K as responsibilities rather than a plugin architecture. Source currently combines policy classification/reference minting/storage in `Reader` and cache/navigation/rendering in `app.js`; this is evidence for reviewing coupling, not proof that a rewrite is needed. Prefer concrete dependencies passed through the existing session/reader ownership. Extract a small typed observation/result contract, query adapter or view module only when a feature has a concrete caller and invariant to share; avoid generic registries, multiple backend generations and speculative compatibility layers. Keep dependency implementations authoritative and closed named storage reads separately owned.

Proposed HLD CRUD: update historical snippet/MCP capability claims and invalid Caller route; add explicit multiple-window and two-observation handoffs; reconcile queued-scope/current-format passages that still repeat schema-34 absence; retain child isolation/current-only admission/exact identity/independent policy/resource bounds; remove superseded assertions only where a maintained successor owns the same contract. Preserve historical status/evidence as history. These remain proposals for feature owners or individually approved Slice 10 items after Slice 9.

## Feasibility questions and reviewer handoff

The known critical question is supported cache-only CPU semantic/hybrid admission under production Default/None and the accepted vector-admission ADR. Future 40 first investigates unchanged supported cache-only/public query routes; this source check disproves the HLD's selected Caller seam, not every possible composition. A proposed route/prerequisite must specify no-fetch/no-repair behavior, actual embedder/profile compatibility, cache TOCTOU handling, model/helper/native ownership and positive real query evidence. No Engine change is authorized here; an unresolved required positive remains unresolved and blocks that feature/release claim.

Other bounded questions: which public snippet route supplies each required lexical observation; exact result-to-origin cardinality for content/passage/windows; shared aggregate budgets across graph traversal and read hydration; clean visibility/queued policy freshness when comparing old observations; finite helper teardown without a public Engine interrupt. Read locked source first. If necessary during execution, investigate only specific questions using primary SQLite/rusqlite/sqlite-vec, Candle or WAI-ARIA/Chromium documentation; no web research or sweep was run to draft this design.
