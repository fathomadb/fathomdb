# Slice 8 — reservation design

The [owner checkout decision](../slice-0/checkout-decision.md) requires future
Slice 0 to create and enter the release branch/worktree from the approved final
planning HEAD. Reuse that release checkout sequentially for 0–9 reports, with
one writer. Other environment/infrastructure changes remain proposals for
actual Slice 9 disposition and conditional Slice 10 implementation. Recording
this ruling and updating drafts performs no checkout creation or slice execution.

## Purpose and authority

Preserve the explicitly empty Slice 8 slot. This is a no-op unless the owner
later assigns reviewed scope. The [plan](plan.md), [adopted scope](../scope.md)
and [master allocation](../plan.md) supply the boundary; no architecture work
is commissioned by naming this file a design.

Inspected baseline: clean `llm/0.8.29-inspector-additional` at
`609dd85c41fb7980e05faa1132a248d376d8ec89` on 2026-11-19; unchanged Engine
base `6edc1155f`, current format 37. The record-browser port is the existing
foundation, not evidence of completed lexical, vector or interactive graph
features.

## Existing versus proposed

The [high-level design](../../../design/high-level-design.md) owns component,
identity, lifecycle and capability contracts. Its authority and capability-map
sections explicitly distinguish architecture from implementation and historical
source findings from current qualification. This slice adds no component,
public callable route, private-storage read, test-only route, protocol, state
or dependency. It makes no claim that a missing route exists or is unnecessary.
There is consequently no source feasibility experiment, web-research question,
new technical challenge or design review to conduct for this reservation.

Canonical needs, requirements and acceptance retain every existing obligation.
The local draft delta is “none,” as captured in the plan. Feature qualification
and quality-roadmap methods remain with their allocated owners; the placeholder
cannot close their tests or create a substitute gate.

## Change control and handoff

A later owner allocation is a scope change, not automatic permission to fill
idle capacity. Before work begins, record its concrete deliverable, ownership,
affected canonical IDs, source-backed feasibility, dependencies and checks in
revised local drafts, and obtain the applicable review of the real design.
Distinguish any Inspector implementation from an external Engine dependency
proposal; do not silently extend the release boundary. A technical allocation
then follows the shared workflow and appropriate behavior-level TDD/review.

Until that happens, Slice 9 receives `reserved; no allocation`, with no invented
research outcome or runtime pass. An explicitly dispatched agent may leave only
the short actual reservation status described in the plan. No status is created
by this draft, no additional worktree is needed, and no cleanup of unrelated
work is permitted.
