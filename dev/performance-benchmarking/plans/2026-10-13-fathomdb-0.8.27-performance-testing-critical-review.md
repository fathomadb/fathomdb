# Critical review: 0.8.27 performance testing plan

**Reviewer:** independent `gpt-6.1-sol` at high effort, read-only, 2026-10-13.
**Scope:** the revised [plan](2026-10-13-fathomdb-0.8.27-performance-testing.md),
actual runner/API code and local input files, plus the referenced vendor
benchmark sources. **Verdict:** two P2 findings, five P3 clarifications; no P1.
The findings below were made on the draft before the final plan corrections.
“Addressed” means the plan now requires a control; it does not claim that
the benchmark code or runs exist.

The reviewer rechecked the corrections and found one additional P2 wording
error: a broad ban on gold in “prompts” would also bar the judge from reading
the reference answer. The plan now limits gold isolation to indexed records,
retrieval snippets, and answerer prompts; only the isolated judge/scorer may
read grading gold. No other P1/P2 issue remained in that recheck.

## Findings and recommendations

| Priority | Finding and evidence | Recommendation | Plan disposition |
| --- | --- | --- | --- |
| P2 | NFCorpus has 3,633 IDs but only 3,593 distinct title-plus-text bodies (40 duplicate pairs). FathomDB `search_text_only` [body-deduplicates before limit](../../interfaces/python.md#direct-fts-only-prefix-stability-0822-slice-23); the test qrels score document IDs independently. The reviewer found 30 test queries with multiple relevant IDs in duplicate pairs and 38 pairs whose qrel relevance differs for at least one query. | Retain official IDs/qrels as the primary product result; freeze the duplicate map and break out affected queries. Label any equivalence-class metric as secondary. Never alter indexed text just to evade deduplication. | Addressed in COMP-01 input and scoring rules. |
| P2 | The local LongMemEval-S file has 10,960 turns carrying `has_answer`, including 896 true values. The prior plan did not prevent these labels entering indexed memory or answerer prompts. The [Hermes parser](https://github.com/lancedb/hermes-agent-memory/blob/main/benchmarks/longmemeval/run.py#L322-L348) keeps label-derived IDs in gold while emitting clean role/content turns; `experiments/extract_01.py` uses the same whitelist approach. | Whitelist indexed and answerer-facing history fields; isolate `has_answer`, support IDs, and reference answers in gold. Test that changing gold leaves indexed text, retrieval snippets, and answerer prompts byte-identical. The judge alone may read reference gold. Retain session/question dates for temporal cases. | Addressed in COMP-03 preparation and mechanism tests. |
| P3 | Three two-arm repetitions cannot put each arm first equally often. | Use four attempts and a fixed, symmetric order. | Changed performance cells to `AB/BA/BA/AB`. |
| P3 | The product v2 runner validates one scoreboard family per run, while the design measures quality and latency from the same ordered hits. | Write one successor result and receipt per physical attempt with both aggregates; render two views from it. | Addressed in implementation work and common measurement rule. |
| P3 | Search query translation differs beyond index tokenization. FathomDB removes short terms/stopwords and ORs remaining terms; LanceDB may not do so. | Pin effective query translation and label native behavior as a product treatment. | Addressed in COMP-01 and COMP-02b. |
| P3 | The crud-bench feasibility check omitted ability to import frozen real corpus/query IDs and export ordered ranked IDs. Its [ValueProvider](https://github.com/surrealdb/crud-bench/blob/main/src/valueprovider.rs) generates template values. | Check import/export before committing to an upstream extension; use the existing product runner with a clearly labeled crud-bench protocol if the upstream change is large. | Addressed in COMP-02a feasibility task. |
| P3 | Filtered FTS acceptance demanded six valid cells even though common support still needs a feasibility check. | Require six attempted cells with typed outcomes; pair only eligible completed operations. | Addressed in COMP-02b acceptance. |

## Remaining implementation checks

- Tests must demonstrate the duplicate-aware diagnostic does not alter the
  official NFCorpus primary score or the top-10 API boundary.
- The LongMemEval converter must fail closed on new input fields rather than
  exposing a newly added gold label to the answerer.
- The successor result/receipt validator must bind both metric families to
  the same ordered-hit artifact and reject a second unbound query run.
- The pinned crud-bench revision must be inspected before choosing its runner
  or the local product-runner bridge. The upstream README's planned workload
  list is not evidence that filtered KNN or build-to-queryable timing runs.

These are acceptance checks for future implementation, not current results.
