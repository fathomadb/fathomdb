# 0.8.24 retrieval-performance conformance findings and TDD plan

## Purpose and boundary

This is the implementation hand-off for the eight FIX-n findings closed in the
design review of the retrieval-performance evidence specification. It records
the defects in implementation terms, names the affected seams, and maps each
one to a red contract test. It does not alter the architecture ruling or make a
performance claim.

The current observed-cost collector and independent runner are local
prototypes. The tests below intentionally fail until the implementation meets
the accepted specification. A passing prototype test is not conformance.

## Findings inventory

| ID | Review finding | Scope | Required remedy |
| --- | --- | --- | --- |
| FIX-1 | “A runner must not reconstruct a workload from an unverified subset of `record.json`.” | Artifact identity and adapter | Stage a versioned canonical workload manifest with digests; consume and verify it before a cell runs. |
| FIX-2 | “Quality provenance is not execution provenance.” | Provenance and evidence-family relation | Capture per-cell execution provenance; keep cross-candidate work distinct and typed. |
| FIX-3 | “A failed cell is evidence, not an exception that erases the planned matrix.” | Sampling and result schema | Persist every planned cell with raw samples plus `complete` or a typed invalidity reason. |
| FIX-4 | “A percentile field with two samples is not a percentile claim.” | Statistical reporting | Gate aggregate fields by the predeclared completed sample count and retain raw samples. |
| FIX-5 | “Same-process fresh-store work is not process-cold, and a warmed query is not warmed ingest.” | Executor treatments | Use exact `fresh_store` and `fresh_store_warm_query` labels; reserve `process_cold` for a witnessed subprocess executor. |
| FIX-6 | “A partial observation must say what was unavailable, rather than silently looking complete.” | Observed-cost schema and collectors | Record per-query observations, typed unavailable reasons, and complete quality environment/provenance. |
| FIX-7 | “A prototype sidecar must not be published as repeated-performance evidence.” | Claim boundary and CLI | Refuse a repeated-performance publication until manifest/provenance/cell/schema requirements hold; retain only an explicitly non-claiming local observation otherwise. |
| FIX-8 | “A sidecar is durable only if schema validation, digests, collision/idempotence, and staging order all hold.” | Writer and shared experiment record | Validate schemas and digests before materialization; stage atomically; make equal evidence idempotent and different evidence a typed collision. |

## Affected surfaces and red tests

### FIX-1 — immutable workload manifest

> “A runner must not reconstruct a workload from an unverified subset of
> `record.json`.”

- Affected code:
  - `src/python/eval/earp/writer.py:write_run` stages the quality manifest,
    binds it to the quality evidence family, and lists the manifest path and
    digest in the durable quality record.
  - `src/python/eval/earp/runner.py:_write`,
    `characterize.py:_write`, `comparison.py:run_comparison`, and
    `answer_arm.py:_write` provide fully resolved workload inputs.
  - `src/python/eval/performance/earp_adapter.py:load_earp_workload` verifies
    the manifest, quality result digest, and resolved-config digest before it
    yields a runnable workload.
  - New versioned artifact schema:
    `src/python/eval/earp/schema/earp.workload-manifest.v1.schema.json`.
- Contract tests:
  - `test_performance_workload_adapter.py` rejects a quality run with no
    manifest and accepts only a digest-verified manifest.
  - It rejects a result-sidecar or resolved-config mutation after manifest
    creation; it never falls back to `record.json` values.

### FIX-2 — separate quality and execution provenance

> “Quality provenance is not execution provenance.”

- Affected code:
  - `src/python/eval/performance/earp_adapter.py:WorkloadRef`, `RunSample`,
    `run_repetitions`, and `write_performance_result` need distinct quality and
    execution provenance structures and a cell-to-execution binding.
  - `src/python/eval/earp/runner.py:_code_provenance`,
    `characterize.py:_git_sha`, and `_experiments.lib.git_info` /
    `env_info` are the quality-provenance inputs.
  - New performance schema records the execution value without copying the
    quality candidate: `src/python/eval/performance/schema/performance.earp.v1.schema.json`.
- Contract tests:
  - `test_performance_conformance.py` requires a complete cell to carry a
    non-empty execution candidate, clean-state, command, toolchain/device, and
    fixture identity.
  - A different execution candidate produces a distinct execution-workload
    digest and `cross_candidate_reexecution`; it cannot join the quality family
    as a same-candidate result. Missing/unverifiable provenance makes the cell
    invalid.

### FIX-3 — typed complete/invalid matrix

> “A failed cell is evidence, not an exception that erases the planned
> matrix.”

- Affected code:
  - `src/python/eval/performance/earp_adapter.py:PerformancePlan`,
    `RunSample`, `run_repetitions`, `_validate_plan_samples`,
    `summarize_samples`, and `write_performance_result`.
  - Diagnostic and characterization bridge executors must return typed cell
    results rather than throwing away a failed cell.
  - New performance schema defines the matrix/cell union and invalidity enum.
- Contract tests:
  - `test_performance_conformance.py` makes one executor cell fail after a raw
    sample and requires a complete matrix containing that invalid cell, error,
    and earlier raw data.
  - The aggregate for an invalid cell is absent/ineligible under the plan; a
    valid sibling treatment remains visible.

### FIX-4 — statistical eligibility

> “A percentile field with two samples is not a percentile claim.”

- Affected code:
  - `src/python/eval/performance/earp_adapter.py:_summary` and
    `summarize_samples`; plan schema must fix aggregation before execution.
- Contract tests:
  - Revised `test_performance_evidence.py` requires one-to-19 valid samples to
    expose only raw samples, min/max, and mean; it forbids p50/p95/p99.
  - It permits p50/p95, labelled descriptive empirical order statistics, only
    at 20–99 samples and p99 only at 100 or more. An incomplete planned cell
    cannot qualify an aggregate.

### FIX-5 — truthful treatment labels

> “Same-process fresh-store work is not process-cold, and a warmed query is
> not warmed ingest.”

- Affected code:
  - `src/python/eval/performance/earp_adapter.py:PerformancePlan`, diagnostic
    and characterization repetition bridges, and `performance/cli.py`.
  - `src/python/eval/earp/runner.py:run_diagnostic` and
    `characterize.py:execute_arm` need an explicit unmeasured query warm-up
    witness only for `fresh_store_warm_query`.
- Contract tests:
  - Revised bridge/CLI tests use `fresh_store_warm_query`, verify it has a
    fresh database plus an unmeasured query witness, and assert that open/write
    phases are still fresh-store phases.
  - Existing `process_cold` refusal stays, with a test that no same-process
    executor accepts that label.

### FIX-6 — complete, explicit observed cost

> “A partial observation must say what was unavailable, rather than silently
> looking complete.”

- Affected code:
  - `src/python/eval/earp/observed_cost.py:Observation` and
    `combine_arm_observations` require a new versioned schema/model.
  - `runner.py:run_diagnostic`, `characterize.py:execute_arm`,
    `comparison.py`, and `answer_arm.py` must emit per-query values, field
    availability/typed reasons, open/projection/readiness witnesses, and full
    execution environment/provenance.
  - `writer.py:_normalize_observed_cost` validates the new sidecar before
    staging it.
- Contract tests:
  - `test_performance_conformance.py` requires every requested observation
    field to be either measured or represented by a typed unavailable reason,
    and requires per-query query samples instead of only an aggregate query
    duration.
  - Existing native diagnostic/characterization observed-cost tests are
    revised to assert this contract on real public SDK execution.

### FIX-7 — no premature repeated-performance claim

> “A prototype sidecar must not be published as repeated-performance
> evidence.”

- Affected code:
  - `src/python/eval/performance/earp_adapter.py:write_performance_result` and
    `performance/cli.py:main` must perform conformance admission before a
    result receives a repeated-performance scope.
  - `src/python/eval/performance/README.md` must describe only the available
    execution semantics.
- Contract tests:
  - `test_performance_conformance.py` proves a run lacking verified manifest,
    complete cell matrix, or execution provenance cannot emit
    `repeated_performance_characterization`.
  - A one-sample complete, verified smoke may retain raw evidence but has no
    percentile/QPS/support claim.

### FIX-8 — durable, validated artifacts

> “A sidecar is durable only if schema validation, digests, collision/
> idempotence, and staging order all hold.”

- Affected code:
  - `src/python/eval/performance/earp_adapter.py:write_performance_result`;
    new performance schema loading/validation module; and
    `experiments/_lib.py:Record`, `write_record`, and artifact handling.
  - `src/python/eval/earp/writer.py:write_run` receives the same manifest and
    artifact-digest discipline on the quality side.
- Contract tests:
  - `test_performance_conformance.py` rejects an invalid sidecar before any
    run directory/index record becomes visible; verifies all advertised
    artifact digests; and asserts index append happens last.
  - Equal durable evidence is idempotent; byte-different evidence at the same
    identity is a typed collision, never an untyped `FileExistsError`.

## Implementation order

1. Introduce manifest/performance schemas and total validation support; add
   digest/canonical-json helpers without altering EARP retrieval schemas.
2. Make `write_run` stage the quality manifest and artifact digests before the
   shared record/index; teach the adapter to verify it.
3. Replace performance sample-only output with typed complete/invalid cells,
   separate execution provenance, and eligibility-aware summaries.
4. Rename treatments and add warm-up witnesses. Implement the observed-cost
   v2 collector only after the new sidecar contract is validated.
5. Gate CLI/publication admission, then satisfy collision/idempotence and
   staging tests.

The implementation must not change Rust/Python/TypeScript production query
semantics, create a release, or turn EARP quality tests into a CI performance
gate.
