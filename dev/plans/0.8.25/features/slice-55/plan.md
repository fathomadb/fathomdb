# Slice 55 plan

## Outcome and boundary

Implement S55-R1 through S55-R7 from the [`design`](design.md): one-page
reciprocal tracing over the normalized Slice 20 relation; synchronous,
strictly bounded operator data-plane integrity checks; and a content-free
structural amendment to the existing opt-in explanation sidecar. Preserve the
accepted `trace_source_ref`, `check_integrity`, `IntegrityReport`, and Python/
TypeScript doctor-method absence contracts.

Persisted trace pages, exhaustive exclusion tracing, frozen integrity jobs,
reverse indexes, repair plans/actions, and semantic correctness claims remain
outside 0.8.25. The implementation adds no schema migration or durable state.

## Delivery sequence and review caps

1. Reconcile the design against implemented Slices 15–50, architecture v2,
   the approved scope adjustment, and current code. Obtain independent design
   review; allow at most four documented FIX-n cycles. Any unresolved P1/P2
   finding blocks READY and implementation.
2. Add one additive successor ADR for the 0.8.8 explanation carrier and update
   Rust/Python/TypeScript/wire/CLI interface documents with the exact design
   contract. Preserve accepted history rather than rewriting it.
3. Commit the first failing tests before product code. Each later reviewed
   requirement increment gets a named RED failure before GREEN. Existing tests
   are read-only during fixes; no snapshot/golden oracle is regenerated by an
   agent.
4. Implement trace and its Rust facade, PyO3/Python, and N-API/TypeScript
   mappings. Implement integrity under `operator` plus the separate CLI verb.
   Extend explanation/correlation only on opt-in paths.
5. Obtain independent implementation review at the exact candidate commit;
   allow at most seven documented FIX-n cycles. Every correction gets a
   focused regression and re-review.
6. Give a separate read-only verifier the exact commit, requirements matrix,
   commands, fixtures, and expected evidence paths. Run focused, fast, heavy,
   all/applicable-feature, fresh-package, and Windows routes.
7. Write `status.md`, update release state through its JSON authority,
   regenerate owned views, run final clean gates, commit, and push the explicit
   release branch. Publication remains out of scope.

## Fault-fixture discipline

The checked-in fixture directory is
`src/rust/crates/fathomdb-engine/tests/fixtures/slice55/`. It contains only
small versioned descriptions and canonical expected wire objects, never a
golden database. Each test creates a fresh database through public writes,
closes/drains as required, then uses one narrowly scoped `test-hooks` mutation
to create exactly one real fault from the design matrix.

Required fault primitives target the actual rows: dependency row schema/ID/
generation, derived owner, derived source link, canonical owner/node,
source-version row, canonical self-link, deletion or duplication of each
required synchronous `search_index`, `search_index_v2`, `search_index_edges`,
`canonical_attributes`, or `property_search_index` member, dense
sidecar/vec0/terminal tuple, generation authority, and only the receipt
readiness subset (`operation_id`, schema/count/outcome/boundary, pending JSON,
and projection generation). An unrelated reason/affected/closure/refusal/
digest/source-reference corruption fixture proves this check stays silent.
There is no reverse-row or reverse-index primitive. After each
fault, the test proves the normal public read fails closed where relevant and
the operator finding is exact. Trace fixtures separately prove that hidden,
ineligible, or independently unverifiable relations match the no-relation
response byte for byte and cannot affect either bound.

The property suites generate bounded valid source/derived registrations, apply
zero or one enumerated corruption, and assert round-trip reciprocity or the
authoritative finding. Seeds, case counts, and minimal failures are recorded in
`implementation-tdd-chronology.md`; failing cases are not promoted to an
agent-generated golden oracle.

### Exact-candidate Python wheel

The focused installed-behavior proof is the repository's fail-closed wheel
verifier, extended by Slice 55 to exercise `trace_dependency`, explained
search presence/normalization, and continued absence of Python doctor methods.
Run it from a clean exact candidate with no `PYTHONPATH`:

```text
test -z "$(git status --porcelain)"
test "$(git rev-parse HEAD)" = "$CANDIDATE_SHA"
wheel_root="$(mktemp -d /tmp/fathomdb-s55-wheel.XXXXXX)"
env -u PYTHONPATH ./scripts/verify-release-python-wheel.sh \
  --python "$(command -v python3)" \
  --wheel-dir "$wheel_root/dist" \
  --venv-dir "$wheel_root/venv"
sha256sum "$wheel_root"/dist/*.whl
env -u PYTHONPATH "$wheel_root/venv/bin/python" -c \
  'import pathlib, fathomdb; p=pathlib.Path(fathomdb.__file__).resolve(); assert "site-packages" in p.parts; print(p)'
env -u PYTHONPATH "$wheel_root/venv/bin/python" \
  src/python/tests/smoke_slice55_installed.py
```

`CANDIDATE_SHA`, the single candidate wheel's SHA-256, the installed module and
native-extension origins emitted by the verifier, and the smoke result are
recorded together. `pip install --no-index --no-deps` inside the verifier and
the origin assertion exclude an editable/source-tree import. A wheel hash or
origin mismatch invalidates the result; no registry artifact is fetched.

### Fresh Linux packages

From an exact-source disposable checkout/environment, retain the wheel result
from the exact-candidate command above, then build a packed N-API package,
record its SHA-256, install offline, and run the local artifact smokes:

```text
./scripts/release/smoke/smoke-npm-package.sh <package.tgz>
./scripts/release/smoke/smoke-crates-cli.sh
```

The package-specific smokes open a real database and exercise
`trace_dependency`, explain correlation/structure, typed trace refusal, and
`doctor data-plane-integrity --json`. The SDK package smokes also prove that
Python/TypeScript still have no doctor integrity method. Package hashes,
source archive hash, toolchain versions, commands, and results are recorded in
`verification-review.md`. These are local ephemeral artifacts only; no release
packaging, registry staging, tag, or publication occurs.

### Windows jobs and native artifacts

The release workflow's `windows-latest` Rust/Python/Node build runs the exact
focused test files plus the existing cross-build. The documented Windows VM,
when reachable, builds from the same source archive and runs:

```text
pwsh -File scripts/release/smoke/smoke-local-native-artifacts.ps1
pwsh -File scripts/release/smoke/smoke-pypi-wheel.ps1 -WheelPath <wheel>
pwsh -File scripts/release/smoke/smoke-npm-package.ps1 -PackagePath <package.tgz>
```

The native smoke includes reciprocal trace, explanation, invalid wire, and CLI

go in `verification-review.md`. VM unavailability is recorded and is not
misreported as a native pass; the mandatory `windows-latest` cross-build still
must pass.

CUDA/GPU and live-model routes are N/A because this slice changes CPU-local
read/diagnostic and explanation metadata only; it does not alter embedding,
reranking, dense dispatch, or model loading. Registry publication is excluded
by the release objective.

## Nonregression and performance evidence

S55-AC7 requires an exact before/after comparison for:

- ordinary search result/order/scores and `explanation=None`;
- explain-disabled SQL plans and the explanation-off allocation/counter probe;
- database, WAL, and SHM bytes around trace and integrity reads;
- existing `TraceReport` and three-section `IntegrityReport` canonical JSON;
- Python/TypeScript doctor-method absence; and
- trace plans using the existing named source/derived lookup indexes with no
  temp B-tree, materialization, or full candidate vector;
- integrity physical scans in fixed class/rowid order and expected-owner scans
  through their named canonical indexes, with no unsupported `ORDER BY`; and
- the 50,000-hidden-dependent trace fixture's VM steps, elapsed time, peak RSS,
  byte-identical response, and absence of a hidden-row-induced bound error.

The verifier records counts, limits, query plans, VM steps, file hashes,
elapsed time, peak RSS, candidate commit, and toolchain in
`verification-review.md`. There is no post-observation threshold rewrite.
Trace `maxWorkUnits` is reported only as an authorized-output classification
bound, never as physical rows visited. A query plan that uses a temp sort or
materializes the full candidate set, any write caused by a diagnostic, or any
default-search hot-path allocation blocks closeout.

## Evidence records and closeout

The durable Slice 55 records are:

- `design-review-cycleN.md` — independent design verdict and findings;
- `implementation-tdd-chronology.md` — every RED/GREEN commit and verbatim
  first diagnostic;
- `implementation-review-cycleN.md` — independent code-review verdict;
- `verification-review.md` — exact candidate, commands, platforms, hashes,
  fixtures, counts, and nonregression evidence; and
- `status.md` — concise final state with links to all records.

The slice closes only when S55-AC1 through S55-AC7 pass, independent review has
no unresolved P1/P2 finding, the release-state JSON and generated views agree,
and final Git status is clean.

## Stop gates

Stop on a public-name collision; SDK doctor exposure; work bounded only by
`max_findings`; multiple snapshots; a reverse dependency row/index; partial
trace/integrity success; endpoint identity disclosure before authorization;
telemetry of caller IDs/content; a second explanation correlation identity;
default-search cost/shape change; repair or persistent state; schema migration;
claiming trace work units bound hidden physical rows; trace temp sorting/full
materialization; an unindexed projection ordering; whole-receipt loading or
unbounded variable-field allocation in `mutation_readiness`; a runtime native
capability discriminator; public-interface drift without parity; or test-oracle
relaxation.
