# FathomDB 0.8.26 draft scope

## Authority and boundary

This file preserves work deliberately postponed from 0.8.24 and 0.8.25. It is
not an active release plan, release-state record, implementation authorization,
or commitment to publish. A future 0.8.26 Slice 0 must revalidate every item
against the then-current `main`, dependency graph, platform matrix, and owner
priorities before producing a dependency-ordered release plan.

No item below may be silently pulled back into 0.8.25. Conversely, removing an
item from a future 0.8.26 plan requires an explicit disposition so postponed
work is not lost.

## Planning constraints

- Start with the normal 0.8.26 environment, dependency, cruft, contract,
  architecture, and verification prework; do not treat this draft as a bypass.
- Keep D26-01 and D26-02 platform work separate unless evidence establishes one
  shared Windows executor/artifact dependency.
- Treat D26-03 as a product/native-stack migration, not routine dependency
  housekeeping. Stop if a replacement changes model behavior without a
  separately accepted compatibility and quality basis.
- Treat D26-04 and D26-05 as independent tool changes so one diagnostic/output
  change cannot conceal the other.
- D26-06 is optional implementation work but mandatory retained scope: the
  future release must either implement a narrow manifest or explicitly retain
  the current navigation with a reason. All underlying evidence remains.
- Publication, registry mutation, hosted-runner changes, and destructive
  cleanup remain separately authorized operations.

## Future Slice 0 intake

The 0.8.26 Slice 0 decision package must enumerate each D26 item as include,
postpone again, reject with superseding evidence, or retain/no change. It must
also reconcile any new dependency/security or platform findings discovered on
the then-current `main` rather than assuming this 2026-09-01 inventory is
complete.
