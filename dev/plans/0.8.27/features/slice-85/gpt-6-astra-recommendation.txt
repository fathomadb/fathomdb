A shared `reader_error` module remains a valid alternative only after its **transitive** dependencies are shown to be below every consumer; the current enum does not meet that condition.

The intended ownership edges then remain:

read / search / graph_expand → filter
read / search / graph_expand → reader_transaction → wal_attribution

There must be no reverse dependency from any handler to `reader_pool`, and no graph dependency on `search::SearchReaderError`. This is the intended boundary graph, not yet an exhaustive claim about all crate imports.

For the gate, I recommend the following exact design:

1. Recursively discover modules from `lib.rs`, including inline modules, out-of-line modules, and declared graph submodules. Resolve imports and re-exports to the item’s defining owner. Record source locations and cfg conditions.
2. Derive local type owners, inherent impl owners, all `impl Engine` methods, and the full Engine field inventory. Maintain separate identities for `graph_expand::types`, `execution`, `traversal`, and `codec`; do not collapse them before SCC analysis.
3. Emit a complete report with edge kinds: composition, contract/type reference, ordinary owner dependency, Engine-field capability access, and callable reference.
4. For root, treat declarations/re-exports/Engine storage layout as composition. Root-owned contracts have explicit item identities and a reviewed admission list. Root free functions and methods are executable item nodes. This catches actual paths through a root helper without inventing a path from one unrelated root function through another.
5. Include ordinary governed type-owner dependencies in SCCs. Exempt only specifically reviewed contract relationships, naming both item and reason. Do not silently exempt every type dependency.
6. Count references to callable items, not just immediate calls. `let f = Engine::search_inner; f(engine, ...)` and `let f = root_helper; f(...)` must establish the edge at the function-item reference.
7. Require owner-qualified free functions by default. For inherent calls, resolve only documented forms: qualified paths, `self`/`Self` in a known impl, typed parameters/locals, and simple reference/dereference/parenthesized aliases. Handle lexical shadowing. A relevant unresolved receiver fails with a suggested explicit form.
8. Count every Engine field access, including closures, references and dereferences. The conservative field-name fallback is acceptable, but diagnostics must label it as conservative; it is not proof that the receiver was Engine.

For duplicate method names, my recommendation is stronger and simpler than “unique among governed types”: any unresolved dot call whose name belongs to a governed cross-boundary method must be rewritten to an owner-qualified call or given a syntactically resolvable receiver. External-type collisions must never be silently assigned to the governed owner. Qualified callable references also solve the function-pointer escape.

The plan should call the output an “exact graph under the enforced source grammar,” not an exact Rust call graph. Macro expansion, trait dispatch, generated code, Deref behavior, and implicit conversions make that distinction material.

Every edge-detection family needs a compiled negative fixture where the tested edge is the only reverse edge. Policy failures such as an unlisted declaration are distinct from cycle failures and should assert the relevant diagnostic. Production mutants should exercise each independent extractor and the actual former cycles; run them on an isolated temporary copy and verify exact restoration. Running the entire mutation suite on every ordinary lint invocation would add unnecessary cost—normal lint should run the gate and its fast unit fixtures; production mutation qualification belongs to gate changes and closeout.

For batching, retain the six stages but split them:

1. Baseline receipts: one evidence batch.
2. Gate: discovery/manifests, path/root graph, Engine fields/methods, and inherent-policy/negative fixtures—four separately reviewable sub-batches.
3. Leaves: one batch each for structural state, attributed transactions, and WAL attribution.
4. Error separation first; then search constructors; then pool request families. Keep one semantic owner or request family per batch.
5. One facade family per batch: read, graph, then search expansion.
6. Enforcement and closeout after the production report matches the reviewed boundary policy.

Use roughly 300–600 non-mechanical changed lines per gate/error batch; split above 800 unless there is a specific cohesion reason. Pure moves can be larger, but should move only one ownership cluster and introduce no behavior changes. Treat these as review-size thresholds, not implementation estimates.

Finally, narrow the invariant to:

> Handler modules never depend on `reader_pool`. Private result and error carriers crossing from handlers to the pool belong to the handler or an explicitly verified lower shared owner. Pool protocol types may depend on those carriers.
