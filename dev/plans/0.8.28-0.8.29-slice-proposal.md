# 0.8.28 and 0.8.29 slice proposal

Owner rulings up to 2026-10-31 are in the W4 section of
`agent-access-block1-finish-plan.md`. Every slice below runs the same
process: requirements and AC, design, design review, TDD (RED then GREEN)
and code review.

## Facts the grouping rests on

- **The MCP crate is not on `dev/0.8.28`.** `fathomdb-mcp` exists only on
  `dev/0.8.29`, as part of Block 1. MCP exposure of the new search flags
  can only land on `dev/0.8.29`.
- **The shared-cache flag is gone upstream.** `libsqlite3-sys` 0.39.1
  (`rusqlite` 0.41.1) bundles SQLite 3.54.1, and its `build.rs` no longer
  sets `SQLITE_ENABLE_MEMORY_MANAGEMENT`. SQLite 3.54.1 is past 3.53.3,
  which carries the Windows WAL path fix. Both exit conditions in
  `third_party/libsqlite3-sys-0.38.1/FATHOMDB-PATCH.md` are met.
- **Refusing old stores is already built.** `open.rs` raises
  `IncompatibleSchemaVersion` for any version but `SCHEMA_VERSION` (34).
- **vec0 can hold the eligibility data.** sqlite-vec 0.1.9 supports
  `UPDATE` on metadata columns, and filters on `=`, `!=`, `<`, `<=`, `>`,
  `>=` and `IN` inside the KNN. It supports no `IS NULL` and no `OR`, so
  unbounded validity is stored as the min or max integer. The 16-column
  limit drops the attribute budget from 13 to 10.
- **The text index keeps old node versions.** Search hides them with
  `superseded_at IS NULL`. Edges delete their vector rows on supersession.
- **Places that change lifecycle:** `write_commit.rs`,
  `record_lifecycle.rs`, `dependency_closure.rs` and `consolidation.rs`.
- **Block 1 follow-ups.** All 19 W1–W8 todos are open and none has
  started. The Block 2 design has not started, and B2-8 (seq 296) still
  needs approval.
