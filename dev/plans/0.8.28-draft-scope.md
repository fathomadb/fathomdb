# FathomDB 0.8.28 draft scope

approved 0.8.25 scope adjustment, the owner-placed Tegra pool work, and four
owner-placed Slice 135 follow-ups from 2026-10-09. It does not authorize
implementation or promotion. The future release must revalidate the consumer
value and measured basis after the narrower data-plane contracts ship.

## D28-08: Tegra private CUDA memory pool

Unlike D28-01 to D28-07, this item is owner-placed scope, not a candidate. It
still needs requirements, acceptance criteria, design, an ADR, TDD and
verification before implementation. Owner rulings of 2026-10-07:

- **Adoption.** Promote the study's private pool created at first use
  (P-first-use) from the `tegra-pool-experiment` feature to the product default
  on aarch64 Linux integrated GPUs. Release threshold 0. Pool size is 1/20 of
  device memory clamped to 2–3 GiB, enabled by default only on the measured
  AGX Orin 64 GB class; 32 and 16 GB Orin, Thor and unmeasured classes are
  opt-in until measured; GB10-class devices need a Tegra-identity condition;
  discrete GPUs keep no pool. Runtime settings with defaults: pool mode
  (`auto`/`on`/`off`, carried per process), maximum size and release
  threshold. Remove the study-only trim arm, comparison variants and
  diagnostics.
- **Typed exhaustion.** The `cuda_pool_exhausted` kind is present and tested
  in Rust, Python and TypeScript on every path, including module-level
  `rerank()` and embedding.
- **Early `cuInit` contract.** FathomDB records whether its module-load
  `cuInit` ran, was opted out or failed. At first GPU use it creates the
  private pool only if early `cuInit` ran; otherwise, or if pool creation
  fails, it uses the 0.8.27 synchronous path. It never refuses. The chosen
  path and the reason are reported by `fathomdb doctor gpu` and the
  allocation-mode diagnostic. Python gains early `cuInit` with the same
  opt-out. An ADR records the rule and settles the Slice 117 import-time
  `cuInit` item the same way.
- **C7 instrumentation, not a fix.** A co-resident library resetting the CUDA
  primary context stays unsupported and documented in 0.8.28; the survival
  fix is 0.8.29 work designed from 0.8.28 data. 0.8.28 adds context-id
  detection (`cuCtxGetId`) on CUDA errors, a typed `cuda_context_lost` error,
  one structured diagnostic snapshot on the first detected loss, context state
  in `doctor gpu`, and the study's reset probe as an expected-crash
  characterization test.
- **Upstream cudarc.** An upstream PR for the pool primitive is a goal. Write
  it upstream-first in upstream style as small commits; the vendored change is
  its backport. Every vendored patch item carries an upstream status and a
  removal path; the aarch64 synchronous fallback stays local. The
  pinned-override gate checks the vendored tree against 0.19.7 plus exactly
  the listed items. Submission needs owner sign-off; 0.8.28 does not wait for
  upstream.

## Constraints

- Callers select profiles explicitly; automatic routing is not in this scope.
- No treatment changes the default without a separately authorized successor
  decision backed by held-out quality, lifecycle, and efficiency evidence.
- Temporal retrieval returns eligible evidence; it does not decide semantic
  contradiction, supersession, or truth.
- Advanced graph evidence must retain source provenance and bounded execution.
