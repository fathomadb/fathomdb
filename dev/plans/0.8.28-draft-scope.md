# FathomDB 0.8.28 draft scope

## Authority

This file preserves bounded advanced-retrieval contracts deferred by the
approved 0.8.25 scope adjustment. It does not authorize implementation or
promotion. The future release must revalidate the consumer value and measured
basis after the narrower data-plane contracts ship.

## D28-08: Tegra private CUDA memory pool

Unlike D28-01 to D28-07, this item is owner-placed scope, not a candidate. It
still needs requirements, acceptance criteria, design, an ADR, TDD and
verification before implementation.

**Execution.** The owner ruled on 2026-10-07 that D28-08 is completed as
0.8.28 **Slice 30** on `release/0.8.28`. That branch was cut from
`release/0.8.27` at `b65283317` while 0.8.27 still has work to do and will not
ship for some days. Until 0.8.27 publishes, merge `release/0.8.27` forward
into `release/0.8.28` before Slice 30 starts and before each of its review
gates, so Slice 30 builds on the current 0.8.27 code. A 0.8.28 plan,
release-state file and board are still to be created; until then this
section is the scope of record and
[the Slice 30 plan](0.8.28/features/slice-30/plan.md) is its working
plan: decisions SD-1 to SD-6, the gate table (G1–G10, each mapped to the
study gates it answers), the design-agent trace instructions, the TDD
ladder, the folded-in study Phase 5 and the HITL host clean-up. Its design
input is [the Slice 30 design draft](0.8.28/features/slice-30/design.md).

Owner rulings of 2026-10-07:

- **Adoption.** Promote the study's private pool created at first use
  (P-first-use) from the `tegra-pool-experiment` feature to the product default
  on aarch64 Linux integrated GPUs. Release threshold 0. Pool size is 1/20 of
  device memory clamped to 2–3 GiB, enabled by default only on the measured
  AGX Orin 64 GB class; 32 and 16 GB Orin, Thor and unmeasured classes are
  opt-in until measured; GB10-class devices need a Tegra-identity condition;
  discrete GPUs keep no pool. Runtime settings with defaults: pool mode
  (`auto`/`on`/`off`, carried per process), maximum size and release
  threshold. Remove the study-only trim arm, comparison variants and
  diagnostics.
- **Typed exhaustion.** The `cuda_pool_exhausted` kind is present and tested
  in Rust, Python and TypeScript on every path, including module-level
  `rerank()` and embedding.
- **Early `cuInit` contract.** FathomDB records whether its module-load
  `cuInit` ran, was opted out or failed. At first GPU use it creates the
  private pool only if early `cuInit` ran; otherwise, or if pool creation
  fails, it uses the 0.8.27 synchronous path. It never refuses. The chosen
  path and the reason are reported by `fathomdb doctor gpu` and the
  allocation-mode diagnostic. Python gains early `cuInit` with the same
  opt-out. An ADR records the rule and settles the Slice 117 import-time
  `cuInit` item the same way.
- **C7 instrumentation, not a fix.** A co-resident library resetting the CUDA
  primary context stays unsupported and documented in 0.8.28; the survival
  fix is 0.8.29 work designed from 0.8.28 data. 0.8.28 adds context-id
  detection (`cuCtxGetId`) on CUDA errors, a typed `cuda_context_lost` error,
  one structured diagnostic snapshot on the first detected loss, context state
  in `doctor gpu`, and the study's reset probe as an expected-crash
  characterization test.
- **Upstream cudarc.** An upstream PR for the pool primitive is a goal. Write
  it upstream-first in upstream style as small commits; the vendored change is
  its backport. Every vendored patch item carries an upstream status and a
  removal path; the aarch64 synchronous fallback stays local. The
  pinned-override gate checks the vendored tree against 0.19.7 plus exactly
  the listed items. Submission needs owner sign-off; 0.8.28 does not wait for
  upstream.

Also in Slice 30 scope (added 2026-10-07):

- **Dependency on 0.8.27.** Slice 30 depends on the embedder-close fix
  (`c816b8653` with `8247d91a4`, on `release/0.8.27`). Without it each closed
  engine keeps its model (about 159 MiB) and the pool's release gates cannot
  pass. Slice 30 does not ship before 0.8.27 publishes with that fix.
- **Qualification on the AGX Orin 64 GB** with the product build, under the
  GPU lock, allocation correctness and release first (study ruling 25). The
  binding list is the gate table in the Slice 30 plan § 3 (G1–G10, with
  the study rows each answers and the rows carried from the study); the
  bullets below summarise it:
  - open/close cycles (C2): no per-cycle growth beyond the study's
    ~0.36 MiB, and reserved memory back to 0 after the last close when no
    module-level model is in use;
  - every fitting allocation succeeds; `reserved_high` never exceeds the cap;
    a full pool returns the typed `cuda_pool_exhausted` in all three SDKs;
  - concurrency at 2, 4 and 8 processes;
  - performance: steady embed, batches 1–128 and rerank within 1.05× of
    the study's P build on Node (so the study's default-pool ratios, rerank
    re-based per study ruling 28, carry over) and faster than the
    synchronous path; Python within 1.15× of Python's default pool (Slice 30
    plan SD-6);
  - output equivalence: identical embedding hash and rerank scores to the
    production build;
  - one 20-minute soak, Node and Python concurrently;
  - early-`cuInit` fallback: with early `cuInit` opted out or failed, the
    synchronous path is used and the reason is reported.
- **Interface and contract updates.** `dev/interfaces/` for Rust, Python,
  TypeScript and the CLI gain the `cuda_pool_exhausted` and
  `cuda_context_lost` error kinds, the pool settings and the `doctor gpu`
  fields, in the same change as the code, together with the ADR.
- **Module-level models.** Document that the module-level embedding and
  reranking models stay loaded until process exit and hold pool memory
  (study ruling 32); the explicit release call is 0.8.30 backlog B30-01.
- **Hardware not available on the study host.** Before any of these classes
  is enabled by default: on-device capacity and heap runs (study C3 and R5)
  for Orin 32 GB and 16 GB; Thor measurement; confirming that GH200 reports
  `CU_DEVICE_ATTRIBUTE_INTEGRATED = 0`; and the Tegra-identity condition for
  GB10-class devices. Until then they stay opt-in or off as ruled.

- **Host clean-up (HITL).** The study's untracked raw data (5.4 GiB on the
  Jetson AGX Orin Ubuntu host: 292 MiB of raw logs, 4.5 GiB of databases,
  the rest builds and virtual environments) is cleaned up after Slice 30's
  qualification closes. Each deletion needs the owner's explicit
  permission, and the owner decides whether a compressed archive of the
  logs is kept first. The path and steps are in the Slice 30 plan § 8. The
  0.8.28 plan carries this as a release task.

## Constraints

- Callers select profiles explicitly; automatic routing is not in this scope.
- No treatment changes the default without a separately authorized successor
  decision backed by held-out quality, lifecycle, and efficiency evidence.
- Temporal retrieval returns eligible evidence; it does not decide semantic
  contradiction, supersession, or truth.
- Advanced graph evidence must retain source provenance and bounded execution.
