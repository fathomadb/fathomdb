## Deviations

- **CMP-C2 without the wheel.** `cuda-preflight.sh` deletes its work
  directory, the built wheel included, so the test plan's
  `c2-embed-rerank.py` through that wheel was not run. Each version instead
  put the venv's `nvidia/cublas/lib` on `LD_LIBRARY_PATH` for the release
  CLI's `doctor cuda-libraries`, the CUDA-05 report test and the embedder's
  live embed and reranker GPU test binaries (built on this tree with
  `embed-cuda,loader-test-hooks` and `rerank-cuda`), the same binaries the
  C3 and S-13 cells use. `pip freeze` of each venv is beside this file.
- **CUDA-03 `module_load_init`.** The test plan expects `"ran"`; the
  early-`cuInit` hook is compiled only on aarch64 Linux, so an x86 CLI
  reports `"not_at_load"`, which is Slice 30's documented behaviour
  (`dev/interfaces/cli.md`). Recorded, not changed.
- **CUDA-04 wording.** R12's RED panic was the fork's load error
  (`Unable to dynamically load the "cublas" shared library for CUDA 12.
  Tried: libcublas.so.12 (wrong version 13.1.1), libcublas.so (wrong
  version 13.1.1)…`), not `Missing symbol cublasCreate_v2`: the fork
  version-checks versioned names at `b777f8d`. The test plan accepts any
  wording.
- **CUDA-11 path.** Candle 0.11.0's F32 matmul calls
  `cublasGemmStridedBatchedEx`, not `cublasSgemmStridedBatched`, so at RED
  the matmul ran on the decoy's stub and returned zeros instead of
  panicking. The GREEN refusal names `cublasSgemmStridedBatched` before any
  device is built, as specified.
