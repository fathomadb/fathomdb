`path`, `reason` and the release threshold agree across the three SDKs in
every cell; `module_load_init` is `ran` (Node, Python hook) or `not_at_load`
(Rust), the two values that design § 14.2 says mean the same path. The
0.8.27 path under `off` is the process's own default-pool-or-synchronous
choice, which differs between processes as in 0.8.27.

**Not measured per SDK: post-close `reserved_current`.** No binding exposes
the pool counters (they are `pub(crate)` test readers in the embedder), so
the matrix cannot read them in a Python or Node process. The close release
is measured at the embedder level, which every SDK's model drop reaches:
R14 at threshold `max`, the two-model test, and R14's threshold-0
regression. A per-SDK counter would need a `test-hooks` reader in each
binding and a test-hooks build of the wheel and the addon; that is left to
the main thread.
