# FathomDB odd-micro experimental review schedule

## Purpose

This inventory preserves experimental work removed from committed 0.8.25
product scope. Each named odd-micro release is a planning review checkpoint,
not an implementation commitment. A review may authorize a preregistered
experiment, move an item to a later checkpoint, or Park it. Product promotion
requires separate requirements, acceptance criteria, design, and evidence.

## Review allocation

| Review | Experimental work | Decision question |
| --- | --- | --- |
| 0.8.29 | Entity/alias expansion; complementary-evidence and coverage-aware selection; MMR/diversity beyond accepted A0. | Can one bounded candidate-selection family improve held-out answer use without correctness, groundedness, attribution, latency, or lifecycle regression? |
| 0.8.31 | Associative PPR/graph diffusion; automatic profile routing. | Has associative retrieval produced a valid gain, and do at least two accepted manual profiles exist so routing solves a real selection problem? |
| 0.8.33 | Full integrity-job orchestration and sophisticated repair planning; exhaustive scale-by-feature-by-CUDA matrices. | Do representative integrity and release tests miss a material failure, and would the added machinery change an operator or release decision? |
| Parked | Database-owned query decomposition, synthesis, consolidation judgment, answer verification, or abstention. | Has FathomDB's approved data-plane boundary explicitly changed? Without that decision, this work remains external-component experimentation. |

## Experimental rules

- Preserve preregistration, fixtures, exact configuration, inputs, outputs,
  receipts, resource/cost records, and negative results.
- An experiment does not create a public API commitment or default profile.
- Retrieval-only and end-to-end answer-system claims remain separately typed.
- A failed or inconclusive treatment returns to experimental inventory; it is
  never rescued through undocumented test-set tuning.
