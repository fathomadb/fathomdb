## Existing controls and their limits

Current product `cuda_pool_policy_tests.rs` contains real pure classifiers for
inactive/replaced/invalid contexts, OOM priority and private-process scoping.
Those test bodies were read; they establish classification, not safe native
destruction. Current ignored Orin reset parent requires exactly one loss
snapshot, teardown-start, no teardown-complete and SIGSEGV11; it uses unbounded
`.output()`. Preserve its historical characterization, then implement an approved
new positive oracle through real TDD; never merely flip the signal assertion.

C's existing sticky-error test and .28 pool tests are historical controls for
their own fault model, not proof of coordinated primary-reset survival. K's
existing private-pool/Tensor and ARM CPU controls are preservation inputs; they
do not close new loss behavior. Historical missing-API RED exceptions recorded
in old fork documents grant no current TDD exception.

## Required fork qualification receipt

Record exact model/fault timing and coordination, independent expected outcome,
full C/K/base/code/test SHAs, per-behavior RED/GREEN assertions/exits, feature and
lock hashes, owned toolchain/compiler/toolkit/image identities, device ordinal/
UUID/context/generation/pool identity, actual loaded library paths/versions/
digests, resource counts/bytes/opaque limits and positive phase timings/status.
Retain all failures/skips and unavailable cells. No installed artifact can be
qualified from an unbound source build.

The reviewed supervisor uses monotonic finite deadlines, concurrently drained
or bounded file-backed output and exact child ownership/reaping; timeout may
contain the failed child but never passes teardown. No `_exit`, process exit
shortcut, abort or kill bypasses Drop to satisfy a positive normal-exit oracle.
Canonical five-second close-return/main-return exit bounds remain; startup,
drain and fault-to-close bounds are separately reviewed. No arbitrary overall
number is selected before fault/venue design.

Freeze each human-intent behavior oracle before its fix. Missing-helper compile
errors, intentional defects or newly passing coverage are not RED. Unit seams
may isolate CUDA dispatch, not mock the database; integration uses a real DB.
No autonomously generated goldens or new CPU/GPU byte-identity promise. Scoped
lint/typecheck/tests precede one final stable source-phase full gate; owned
native/Python/TS tools and fresh independent final review remain required.
