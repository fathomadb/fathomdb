# Slice 160 requirements and acceptance

The [master release needs](../../../plan-0.8.29.md#draft-release-needs-requirements-and-acceptance-allocation),
[canonical requirements](../../../../requirements.md), [acceptance](../../../../acceptance.md)
and accepted ADR successors own contracts. These six local joins add no ACs.

| Need / requirement | Falsifiable local acceptance | Release need |
| --- | --- | --- |
| N160-1 / R160-1: scope is truthful | A160-1: every selected mandatory slice has actual reviewed exit evidence or an actual authorized disposition; each conditional exclusion has its failed/not-selected condition and residual consequence. Unknown mandatory work blocks readiness. | All |
| N160-2 / R160-2: integrated behavior is qualified | A160-2: matrix rows bind current relevant source/features/toolchain/fixture/native inputs; full source-phase workspace, feature, strict security and required long/performance scopes actually execute. Fail/skip/excluded/resumed counts remain distinct. | R29-REL-A/S/R |
| N160-3 / R160-3: public boundaries agree | A160-3: text-default and structured-opt-in MCP tools/errors/filter/flags/budget/paging/lifecycle and approved B2 behavior match independent intended outcomes and affected Rust/Python/TS contracts on identified current artifacts. Historical conformance failures have real resolution, not inherited waivers. | R29-REL-A/K |
| N160-4 / R160-4: support claims have consumer proof | A160-4: supported five CPU/native targets, distinct Windows WAL and selected CUDA/artifact/SDK rows satisfy their actual contracts. Required unavailable rows are blocked; unsupported cells are not advertised. A build or source test alone never supplies installed-package proof. | R29-REL-K/G/D |
| N160-5 / R160-5: candidate is deliverable | A160-5: version/notes/interfaces/docs and nonpublishing local plus separate release rehearsal agree with the immutable candidate. | N160-6 / R160-6: published consumers really work | A160-6: only after separate publication authorization, all required publishers and fresh registry-installed consumers pass exact-version identity, persisted write/read, missing-record, separate-process reopen, close and process exit. Partial publish is incomplete. | REQ-048/049/050/052 |

Keep locked numerical thresholds and fixture pins. AC072/073/075/076/081 are
binding in their accepted scopes; synthetic recall/stress are report-only and
AC020's ratio is retired. AC083100k80/300ms is tracked, not a numerical release
gate. Accepted TC5 fidelity replaces legacy EU7 recall for this execution;
legacy stress and its actual failing overall exit remain separate.

Fresh evidence is required for release-specific measurements, changed relevant
inputs and final distributed bytes. Current unchanged evidence can close existing
correctness/inherited rows within its actual scope. See [matrix](qualification.md)
for concrete freshness, gates and exclusions; [test map](test-map.md) names oracles.
