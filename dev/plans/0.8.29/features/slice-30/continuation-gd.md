## Minimal G observer contract (new, feature-gated)

Proposed engine nondefault `slice30-observer` feature and SDK feature forwarding
only that engine feature. Shipped facade/Python/TS/MCP/CLI feature lists do not
forward it. No environment knob, public counter/result/configuration change,
process-global collector, SQL callback replacement or cache is added.

Proposed exact test surface, named/doc-hidden and documented in rust.md in the
same source change:

```rust
Engine::begin_slice30_observation_for_test(max_records: usize)
    -> Result<Slice30ObservationGuard, EngineError>;
Slice30ObservationGuard::with_operation<R>(operation_id: u64, work: impl FnOnce() -> R) -> R;
Slice30ObservationGuard::take(&self) -> Slice30ObservationBatch;
```

The SDK begin method forwards internally to its own core and returns the same
engine guard type through `fathomdb_sdk::Result`; engine errors retain the normal
SDK error translation. It does not expose the core engine. Guard is neither Clone nor Send and is
owned by one measurement thread; one session per engine, invalid max outside
1..=32768 or already-active observation returns typed existing InvalidArgument.
Closed/closing begins use existing Closing. A guard's Drop disarms only its own
session identity, releases all retained records, and does no SQL/provider work.
No guard holds an Engine alive; in-flight request tokens use weak collector
references. Dropping a guard/closing an engine cannot block worker completion.
Nested with_operation restores prior TLS on unwind. Tokens include engine and
session identity; a closure calling another engine does not collect that engine.
Copy the token explicitly into SearchReaderWork; no ambient worker-thread guess.

`take` atomically drains at most the configured bound; output contains monotonic
session sequence, records, dropped-record count and collection issues. Hot append
uses bounded storage and try_lock; overflow/contention increments dropped count
without failing/changing product outcomes. The driver takes records after each
operation or fixed16-operation boundary, outside API clocks. Drops/issues mean
attribution INCOMPLETE, never zero work. There is no I/O/subscriber callback in
hot instrumentation. Internal creation/transport hooks are cfg-gated; default
product builds have neither observer state nor observer clocks.

Each record has engine/session/operation identity, phase, unique span ID, optional
parent span ID, monotonic start/end ns, status and minimal numeric/enum facts.
Status is `ok`, `error`, `not_run` or `unavailable`; skipped phases have no
start/end duration. Facts distinguish boolean predicate result, function-entered
and SQL-executed; missing facts remain optional, never false by default.
No durations fabricated from missing fields. One fixed monotonic origin belongs
to the collector; elapsed values from other origins are not joined. A span's
inclusive wall time is labelled inclusive. Only demonstrated nonoverlapping
children can yield an exclusive remainder; otherwise report a time tree, not
additive shares. No percentile subtraction or hybrid-minus-embed proxy.
