# Slice 2 disposition design

## Existing substrate and proposed delta

Current substrate already has a thin map/detail split, authoritative accepted
ADRs/interfaces, superseded architecture banners, design lifecycle catalog,
state-owned generated views, archive-in-place precedent and meaningful tests
whose filenames still say scaffold. Keep them. This phase changes only the local
proposal, correcting stale dispositions and evidence classification.

For each bounded cohort: inspect content → identify current authority → inspect
literal/inbound and discovered nonliteral consumers → classify → record
preservation, risk/confidence and receiving owner → reviewed proposal. Prefer
an in-place current-authority correction where that is already selected for10.
An archive-in-place label means retain bytes/path as history; it never authorizes
a physical move. Deprecate-in-place applies to misleading execution/current-status
claims, not silent withdrawal of a contract.

## Consumer proof and uncertainty

- Distinguish a tracked program's read from its output declaration. The L2 registry
  generator actually reads two old JSON results; preserve those inputs and outputs.
- Check Cargo/pytest discovery and package readme declarations; “scaffold” and
  “dead_code” names do not prove non-use. MCP ToolResult feeds output schema.
- Follow navigation and generator source ownership. Do not hand-edit generated
  contributor pages, release-state regions or catalog classes to suppress warnings.
- Preserve original measurements, failed/negative results, human adjudications,
  minimized cases and measurement tools. Current status can point forward while
  old candidate-bound results remain accurate for their original dates.
- A no-hit local filename search covers only literal tracked references in its
  declared scope. Dynamic paths, external scripts, ignored datasets, remote refs
  and other checkouts remain outside that proof. Unknown consumers mean retain.

## Scope decisions and failure modes

No live move/delete recommendation remains. The query placeholder is retained by
explicit owner ruling despite its tautology; other templates hold real reopen/
registry/cursor assertions. No test discovery run is necessary to honor Keep.
.27 Slice90 later reconciles recovery qualification, but does not rebind85.
Optional annotations link that chronology rather than changing historical tests,
receipts, generated state or earlier failure counts.

Current10 corrections cover DOC-INDEX status, format37 applicability, v2 workspace
membership and package/setup prose already selected in T10-6. Semantic fusion,
hints omission, coverage coordinates and error contracts stay with3/4/50–90.
No broad cleanup, new migration, erasure campaign, CUDA maintenance or shell/cache
reclamation is derived from this inventory. Preserve .30 allocation and host/tool
constraints from0. Missing future capacity cannot be “solved” by deleting history.

## Review and implementation boundary

Parent controls independent design PASS → proposal finalization/scoped checks →
fresh output review → serial import. After import, scoped Markdown checks must
report real exits. Later public docs use their own validator/generator freshness
checks; behavior/script work uses TDD and source verification in its owning slice.
Future destructive retirement would require a separate reviewed authorization,
exact destination/preservation map and consumer proof. It is no prerequisite to2,
10, or .29 release work under the current selected scope.
