# Slice 5 adequacy review design

## Method and existing versus new work

Use the22-obligation [join](traceability.md) and [requirements](requirements.md).
Existing queue accounting, native eligibility, fusion formula, Unicode selector,
span storage, overload conversion, physical erasure/crash and witness-parser
controls are retained. New work belongs at the changed seam; absence of current
execution is not automatically an absent test or product defect.

For each oracle ask which plausible wrong behavior it would reject. Independently
seed expected IDs, revisions, provenance, bytes or post-state before comparison.
An optimized/reference pair sharing production eligibility/fusion can share the
same defect; pair comparison with human-specified tiny truth fixtures. A manually
maintained inclusion subset or duplicated same-file parity literals cannot prove
live surface parity. Use actual introspection and a shared accepted contract
where appropriate. Narrow mutation controls are useful only to demonstrate the
specific oracle detects its claimed violation; no global mutation score is added.

No test is written/run in5. The following are future receiving-owner designs.
Before each behavior fix, stage/commit a genuinely failing RED with its assertion,
real exit/source/selector evidence, then implement GREEN with the oracle frozen.
Compile/import failures qualify only for genuinely absent public behavior and
must be followed by semantic GREEN assertions. Existing intent changes require
the accepted successor first; never regenerate a snapshot/golden to mask drift.
Pure qualification/measurement has explicit reached/control/result evidence,
without pretending an existing passing regression is a new failing-first fix.

## Evidence and execution budget

Effort classes in [findings](findings.md) are comparative: S bounded fixture or
document check, M several owned seams, L approved hardware/artifact campaign.
They are not measured runtime/cost promises.10 reserves owned tools/resources;
affected fault/study/artifact owners establish exact host/access/window/caps.
No extra hardware, priced run, driver/toolkit change or broad campaign follows
from a local test-adequacy recommendation.

Keep original source/configuration, commands, raw logs, real exits and counts,
corpus/model/fault/seed and artifact digest/ABI/features. Record historical,
source-only, synthetic, skipped, diagnostic and current executed scopes separately.
Reusing evidence requires unchanged relevant inputs and an explicit comparison;
changed fusion/cache/pins/reporting trigger affected composed reruns. A successful
scoped rerun closes its named failure; it does not rewrite a failed full campaign.

Apply scoped validators for this documentation. Later source phases retain strict
owned full verification, required feature/long selectors and full workspace
clippy/check, once on final stable inputs with affected reruns. Do not launch
extra full gates to validate prose or rebuild solved .28 delivery/CI mechanisms.
