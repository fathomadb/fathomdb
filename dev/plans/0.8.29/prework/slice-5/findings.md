# Slice 5 findings and proposed priority

Prioritize changes at selected seams, not new broad test programs:

1. 20: deterministic pre-enqueue admission/drain proof. Existing queue resource
   controls are strong; preserve them, add the narrow missing scheduling window.
2. 40/50: actual snapshot/time/view cache truth and independently expected record
   identity/provenance; current body-dedup tests require a contract successor.
3. 60/70/80/90: text-filter/default successor, bounded error vocabulary and both
   formats' real budgets/paging/unknown span coordinates. Preserve existing
   feedback/concurrency/Unicode/storage oracles.
4. 100: compare existing strong physical/reopen tests before selecting only
   uncovered accepted abrupt interruption boundaries. Erasure feature stays done.
5. 110: characterization currently passes by expecting SIGSEGV; safe teardown
   needs a distinct positive oracle and approved venue. Do not run faults here.
6. Conditional graph weak oracle: strengthen only if selected identity/graph
   changes touch the behavior, otherwise explicitly defer.

The plan's full-product adequacy criterion remains bounded by uninspected
native/SDK/platform/fault paths; Slice9 must accept/defer those evidence gaps.
No current execution, blanket coverage target, automatic expensive campaign or
independent review is claimed by this research output.
