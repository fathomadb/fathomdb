# Slice 6 review design

Use claim → audience → accepted authority → current source → discrepancy →
proposed owner. An old date alone is not a defect. Keep historical evaluation
evidence and annotate its applicability; never rewrite it into current proof.

Source-only inspection can justify a documentation proposal, not a successful
runtime example. Contract changes wait for their feature implementation and
ADR/interface review. Generator-owned pages change through their inputs.
Conflicting authorities go to Slice 9, rather than editorial selection.

Scope sampled: published install/version claims, MCP result/filter contracts,
contributor setup, release publisher/qualification claims. Slice 2 supplies
retention/inbound-reference evidence before any archive/delete proposal.
Slices 3–5 reconcile semantics and test adequacy. One parent writes these drafts.
No full qualification or new assurance framework is needed for this audit.
