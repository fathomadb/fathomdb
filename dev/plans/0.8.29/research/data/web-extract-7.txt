L2: 
L3: 【2†release/packaging】
L4: 
L5: 【3†atalman】 September 23, 2026, 8:29pm 1
L6: 
L7: TL;DR — Starting the week of Monday, Sept 28 2026, we are removing CUDA 13.0 from the PyTorch nightly build matrix and CI. Nightly CUDA builds will be 13.2 (stable / default) and 13.4 (prototype). No GPU architecture support is lost. PyTorch 2.14 and earlier are unaffected. If you pin `cu130`, move to `cu132`.
L8: This is tracked in 【4†pytorch/pytorch#190385†github.com】.
L9: 
L10: * * *
L11: ## Why we are removing it
L12: 
L13: CUDA Toolkit 13.2.2 fixes a compiler bug that has been present since CUDA 12.8. Compiler-inserted thread reconvergence could fail and leave stale or corrupted values in registers, producing silently incorrect results — no crash, no error, just wrong numbers.
L14: The bug only triggers in kernels with two or more nested levels of thread divergence, where the compiler elided convergence instructions for one or more of those levels. Kernels with a single level of divergence are unaffected. From the illustrative example in the NVIDIA notes:
L15: 
L16:     `__global__ void affected(const int* in, int* out) {
L17:         int tid = threadIdx.x;
L18: 
L19:         if (tid < 16) {             // Level 1 divergence
L20:             if (in[tid] > 0) {      // Level 2 divergence, nested
L21:                 // A register written here can carry a stale value
L22:                 // across the reconvergence point.
L23:                 out[tid] = compute(in[tid]);
L24:             }
L25:             // Implicit reconvergence: failure can manifest here.
L26:         }
L27:     }
L28:     `
L29: Details: 【5†CUDA Toolkit 13.2.2 release notes†docs.nvidia.com】.
L30: 
L31: CUDA 13.0 predates the fix. Since 13.2 already provides identical architecture coverage, continuing to build and ship a toolkit with a known silent-miscompilation class buys us nothing and exposes users to it. Thanks to 【6†@DEKHTIARJonathan】 for raising this on the RFC.
L32: ## What you need to do
L33: 
L34: If you install the default nightly — nothing. You will start receiving a CUDA 13.2 build instead of 13.0.
L35: 
L36: If you pin cu130, update the index URL:
L37: 
L38:     `-pip install --pre torch --index-url https://download.pytorch.org/whl/nightly/cu130
L39:     +pip install --pre torch --index-url https://download.pytorch.org/whl/nightly/cu132
L40:     `
L41: If you maintain CI that references cu130 nightly artifacts — Docker tags, index URLs, build-matrix entries — please update to cu132 during the week of Sept 28. Builds stop being produced after the change lands; pinned references will go stale rather than fail loudly.
L42: ## Feedback

L343: ### 2.5.3. CUDA Tile IR【49†】
L344: 
L345:   * A `cuda_tile.loop` or `cuda_tile.for` operation may fail compilation or produce incorrect results when a tile produced by a load is carried between iterations. The issue may occur when the next iteration’s tile is loaded before the carried tile’s final use. As a workaround, place the next load after the carried tile’s final use, or restructure the loop so the loaded tile is not carried between iterations.
L346:   * Converting a `tf32` tile loaded from global memory to `f32` may produce incorrect values if the lower 13 mantissa bits of any loaded value are nonzero. These bits do not affect MMA operations on the loaded tile; the issue becomes observable only after conversion to `f32`. As a workaround, ensure that the lower 13 mantissa bits of every `tf32` value loaded from global memory are zero.
L347:   * An indexing signedness issue can cause miscompilation to TMA for view-based memory operations when the underlying tensor has a large number of elements. Loading or storing to a view whose underlying `cuda_tile.tensor_view` has 2^31 elements or more along a single dimension can trigger the miscompilation. As a workaround, limit the size of tensors to 2^31-1 per dimension, or set the `allow_tma` optimization hint to `false` on affected loads and stores.
L348:   * The specifications of `cuda_tile.scan` and `cuda_tile.reduce` implicitly allow several behaviors that are not yet fully supported. The body of a scan or reduce op capturing SSA values from an enclosing scope, using non-scalar intermediate tiles, or nesting region-bearing operations may cause miscompilation.
L349:   * Floating-point atomic addition (`addf`) in `cuda_tile.atomic_rmw_tko` and `cuda_tile.atomic_red_view_tko` currently flushes subnormal values to zero. This behavior is not intended and is expected to change in a future compiler version; programs should not rely on it.

L25: If you are on a Maxwell, Pascal, or Volta GPU, PyTorch 2.14 is the last release with a prebuilt wheel for you. From 2.15 onward you will need to either stay on 2.14 (or earlier), or compile PyTorch from source against a CUDA 12.x toolkit.
L26: 
L27: Linux aarch64 loses nothing. The CUDA 12.6 aarch64 build covered Ampere and Hopper, both still covered by the CUDA 13.x builds, which additionally add Blackwell.
L28: ## What remains
L29: 
L30: CUDA 13.x builds continue and cover Turing (7.5) through Blackwell. The exact set of published CUDA versions changes from release to release, so check the getting-started page for the current list rather than pinning to what is written here: 【6†https://pytorch.org/get-started/locally/†pytorch.org】
L31: ## Installing 2.14 today
L32: 
L33: If you need CUDA 12.6, pin to 2.14 while it is current:
L34: 
L35:     `pip3 install torch==2.14.0 torchvision==0.29.0 --index-url https://download.pytorch.org/whl/cu126
L36:     `
L37: ## Building from source for CUDA 12.6
L38: 
L39: This is the supported path for pre-Turing GPUs from 2.15 onward. Install a CUDA 12.6 toolkit, then build with the architectures you need:
L40: 
L41:     `git clone --recursive https://github.com/pytorch/pytorch
L42:     cd pytorch
L43:     export TORCH_CUDA_ARCH_LIST="5.0;6.0;7.0"   # Maxwell / Pascal / Volta, adjust to your GPU
L44:     python -m pip install -r requirements.txt
L45:     python setup.py develop
L46:     `
L47: Full instructions: 【7†GitHub - pytorch/pytorch: Tensors and Dynamic neural networks in Python with strong GPU acceleration · GitHub†github.com】
L48: 
L49: Because one CUDA 12.6 build is retained in CI, breakages in the 12.x compile path should surface on our side rather than yours. If you do hit one, please file an issue — that build exists precisely so this configuration stays buildable.
L50: ## Timeline
L51: 
L52:   * 2.14 (released) — CUDA 12.6 shipped as a legacy published build; deprecation announced in the release notes. These binaries remain available.
L53:   * Mon 7 September 2026 — CUDA 12.6 removed from the nightly CD builds. No further 12.6 nightlies published.
L54:   * 2.15 — CUDA 12.6 removed from CD entirely; no wheels or libtorch archives built or published. One CUDA 12.6 build stays in CI as a compile check.
