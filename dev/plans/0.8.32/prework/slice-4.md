## 2. CRITICAL ARCHITECTURAL FINDINGS FOR HITL GATE 1

### CRITICAL-1: Schema 38 `vector_default` (`vec0`) has NO `scope` column on disk, and `ensure_vector_partition` fails closed on `0.8.31` stores

- `vector_storage.rs:74-99` defines **only 7 built-in metadata columns** plus up to 8 `attr_*` slots (the 16th slot is *unallocated*, not present in Schema-38 DDL; verified on `golden-0.8.31-schema38.sqlite`).
- `ensure_vector_partition` (`vector_storage.rs:41-72`, called at `open.rs:1390`) fails closed with `InvalidQuery` on any DDL mismatch. Naively adding `scope TEXT` would refuse to open every `0.8.31` DB.
- `reshape_vector_partition_nondestructive` (`vector_storage.rs:369-375`) joins `LEFT JOIN canonical_nodes cn` only, omitting `canonical_edges` (`edge_fact` vectors).
- **Resolution (`P4-01`):** Accept both 7-col and 8-col (`scope TEXT DEFAULT ''`) layouts in `ensure_vector_partition`; activate `scope TEXT` via lazy/writable-open `reshape_vector_partition_nondestructive` (fixing `LEFT JOIN canonical_edges ce` + `COALESCE(cn.scope, ce.scope, '')`); keep a `canonical_nodes` preselection/post-filter fallback for read-only legacy 7-col stores.

### CRITICAL-2: Schema-38 `scope` lacks `operational_collections` / indexes, AND store-wide uniqueness permits cross-scope overwrite

- `STEP_38_SQL` (`fathomdb-schema/src/lib.rs:161-165`) adds `scope TEXT NOT NULL DEFAULT ''` to `canonical_nodes`, `canonical_edges`, `operational_mutations`, and `operational_state`, but **not** `operational_collections`, `canonical_property_values`, or `_fathomdb_actuation_receipts`, and creates **zero `scope` indexes**.
- `canonical_nodes_logical_active_idx(logical_id)`, `canonical_edges_logical_active_idx(logical_id)`, and `operational_state PRIMARY KEY(collection_name, record_key)` (`ON CONFLICT DO UPDATE` at `write_commit.rs:974-982`) are **store-wide unique**. Without an explicit ownership check, Scope B writing/transitioning an existing `logical_id` or `(collection_name, record_key)` silently overwrites Scope A's row! Rewriting PKs requires breaking `SCHEMA_VERSION = 39`.
- **Resolution (`P4-02`):** Ratify **store-wide `logical_id` / `(collection_name, record_key)` uniqueness with strict same-scope ownership guard** under `SCHEMA_VERSION = 38` (cross-scope collision refuses atomically); declare `operational_collections` schemas store-global (row-level `scope` in `operational_state`/`operational_mutations`); add idempotent boot partial indexes `WHERE scope != ''` leaving `frozen_read` page indexes intact and preserving single-scope `200.4 MB` DB-size headroom.

### CRITICAL-3: SQLite `PRAGMA synchronous = NORMAL` (`open.rs:1262`) vs. Slice 50 `dm-flakey` Power-Loss Oracle

- `open.rs:1255-1263` runs `PRAGMA journal_mode = WAL; PRAGMA synchronous = NORMAL;`. Under real storage power loss (`dm-flakey` `drop_writes` + QEMU power-off), `NORMAL` guarantees zero corruption / atomic rollback, **not** zero loss of un-checkpointed WAL commits.
- **Resolution (`P4-07`):** Preserve `SyncMode::Normal` default (holding `0.8.31` write speed `32.8 ms`/`15.5 ms` with honest WAL checkpoint-bounded durability) AND add opt-in `EngineConfig` `SyncMode::{Normal, Full}` (`PRAGMA synchronous = FULL`), qualifying **both** profiles in Slice 50's VM `dm-flakey` oracle.

### CRITICAL-4: `fathomdb-mcp` Writes & `latest_state` Checkpoints Lack an Atomic Governed Engine/SDK Seam under `MR-070.2`

- `fathomdb-mcp/tests/manifest.rs:41-62` enforces `MR-070.2` (`fathomdb-sdk` only; zero `rusqlite` / `fathomdb-engine`).
- `ActuationOperationV1` supports nodes/edges/dependencies/lifecycle but **no `latest_state` (`operational_state`) checkpoint op**, `_fathomdb_actuation_receipts` (`lib.rs:1096`) has **no `scope` column**, and `Engine::write` supports `OpStore` without `operation_id` / `expected_write_boundary`.
- **Resolution (`P4-10`, `P4-11`):** Extend the atomic engine+SDK transaction seam (`ActuationOperationV1::PutLatestState` or governed `IdempotentWrite` + scope-bound `_fathomdb_actuation_receipts`) and wire `EP-07` (`open_without_create`) + `EP-01` (`read::visibility_state`) cleanly through `fathomdb-sdk`.
