# FathomDB 0.9.0 backlog

Candidate work for release planning, not an executable release plan. The owner
placed the Vercel UI SDK research here at seq-404. No 0.9.0 implementation,
release-state activation or publication is commissioned by this placement.
Current session work remains focused on 0.8.30 robustness and its approved plan.

## Agent data interfaces informed by Vercel UI SDK

Preserve these inputs for 0.9.0 scope selection:

- [UI SDK review](../../notes/agent-storage-sdk/01-vercel-ui-sdk-review.md):
  composable behaviors, version-matched package documentation and semantic tools.
- [Agent/harness reflection](../../notes/agent-storage-sdk/02-agent-harness-mechanisms.md):
  discovery, actions, permissions, result semantics and transport boundaries.
- [FathomDB proposal](../../notes/agent-storage-sdk/03-fathomdb-agent-storage-proposal.md):
  package-local documentation and tested data recipes, followed by a bounded
  SDK-hosted evidence workflow and a separately reviewed mutation profile.

At planning, revalidate the upstream SDK and current FathomDB capabilities.
Select a bounded experiment and acceptance criteria against the existing typed
SDK, MCP, evidence, provenance, lifecycle and actuation contracts. Compare
verified task outcomes, repairs, token/call cost and latency; do not adopt
Vercel's benchmark results as a FathomDB performance promise.

This backlog preserves research for review. It does not approve every proposed
API, new MCP tools, universal namespaces, multi-source provenance, write trust
policy or an engine redesign. Those require their applicable design and scope
decisions. The research introduces no additional 0.8.30 feature work.
