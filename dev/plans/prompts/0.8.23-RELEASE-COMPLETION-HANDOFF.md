# 0.8.23 release completion hand-off

Finish the release. The product work is complete; this is CI closeout, not another verification or development pass.

- Do **not** add tests, gates, workflow checks, process, documentation scope, or product changes for confidence.
- Do **not** rerun a passed local or GitHub job. GitHub is confirmation, not diagnostics.
- If a required job fails, reproduce that named failure locally on the matching platform, then make only the smallest
  necessary P0/P1 fix. Do not broaden the test or CI surface.
- No tag, publication, registry promotion, or GitHub release. Push only `release/0.8.23` until it is merged.
- Check GitHub no more than once every five minutes. Use windchill3 for Linux/CUDA, the local Windows VM for Windows,
  and the established Jetson runner only for Tegra work.

1. Start from a clean current `origin/release/0.8.23` worktree. Read the retained local-gate output. If the existing
   `scripts/check.sh` run is still active, wait for its `CHECK_EXIT=0`; do not restart it.
2. Push the exact clean candidate HEAD to `origin/release/0.8.23`.
3. Let the release PR’s normal GitHub CI run once and pass.
4. Use the existing main-owned, candidate-SHA-bound CUDA dry-run authorization as designed; do not weaken it. Run one
   non-publishing dry-run from `main` against that exact candidate and retain its receipt.
5. When normal CI and the dry-run pass, merge `release/0.8.23` to `main`. Confirm post-merge CI once.
6. Update status only from Git and retained artifacts. State that tag/publication and post-publish smoke remain
   unperformed and require separate HITL.

Escalate only for a locally reproduced P0/P1 release blocker, an unavailable required GitHub authorization/runner,
or a request to tag or publish. Do not invent additional finish lines.
