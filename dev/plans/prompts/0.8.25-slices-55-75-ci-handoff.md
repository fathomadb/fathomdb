## Per-slice engineering loop

Use the release worktree as the single writer. Review and verification agents
must be read-only in that checkout.

1. **Orient and reconcile.** Confirm predecessor closure from Git and the
   release-state writer. Compare plan/design with current code, requirements,
   acceptance criteria, architecture, interfaces, and implemented
   predecessors. Update the design only when evidence requires it.
2. **Design review.** Obtain an independent design review before code. Allow at
   most four documented FIX-n cycles. A slice cannot become READY with an
   unresolved implementation-shaping P1/P2 finding.
3. **TDD RED.** Add real-database tests that fail for the intended reason and
   preserve the RED in Git. Do not mock the database or generate a new oracle.
4. **GREEN/refactor.** Implement the smallest contract-complete behavior.
   Preserve Rust/Python/TypeScript and wire parity for public changes. Never
   weaken a correct test to make implementation pass.
5. **Implementation review.** Give an independent read-only reviewer the exact
   commit. Up to seven FIX-n cycles are planned; an eighth is owner-authorized
   if genuinely necessary. Record every cycle and reviewed SHA.
6. **Independent verification.** Use a separate read-only verifier for focused
   acceptance, parity, platform, applicable feature, and repository gates. A
   discovered defect returns to committed RED/GREEN and review.
7. **Close durably.** Write the slice status and review/verification records.
   Edit only `dev/plans/release-state-0.8.25.json` for release facts, then run
   `./scripts/check-release-state-views.sh --write`. Never hand-edit a generated
   block. Run final checks, commit, and push the explicit release branch ref.
8. **Checkpoint and compact.** Write reusable lessons to the external memory
   store, update its `MEMORY.md`, confirm a clean synchronized branch, and
   compact context before opening the next slice.

Never skip hooks, rewrite branch history, delete retained run data, or hide a
failed or skipped route. All experiment inputs, outputs, receipts, and raw data
needed for repeatability must remain retained.
