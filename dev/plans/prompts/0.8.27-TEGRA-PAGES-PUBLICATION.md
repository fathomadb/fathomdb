# 0.8.27 Tegra Pages publication handoff

You are completing the separately authorized publication of
`fathomdb==0.8.27+tegra` and the `fathomdb-linux-arm64-gnu-tegra` 0.8.27 Node
tarball for a classic Jetson Orin. The goal is to build, validate, deploy, and
post-deployment smoke-test only those two Tegra artifacts through the
first-party Pages site after explicit release authorization. Do not create or
move a tag; do not publish to PyPI, npm, crates.io, or GitHub Releases; do not
replace generic artifacts. The main `fathomdb@0.8.27` npm package must already
be on the registry, because the Node smoke installs it from there.

## Procedure

1. Confirm `gh auth status`, the remote `release/0.8.27` head SHA, and a clean
   checkout. Confirm the candidate SHA equals that remote head.
2. Read `docs/operations/tegra-pages-publication.md` and run:

   ```bash
   scripts/release/publish-tegra-pages.sh \
     --candidate-version 0.8.27 \
     --candidate-sha <exact-remote-head>
   ```

3. The script dispatches the manual `Jetson Tegra CUDA evidence` workflow with
   `publish_to_pages=true`. In one run that workflow:
   - builds the host-native CUDA wheel with Maturin 1.14.1, proves static
     CUDA-runtime linkage, runs installed CPU/auto/forced-CUDA smoke paths,
     and validates the allocation witness;
   - builds the Tegra Node package and smokes every policy from a fresh
     installed consumer;
   - imports the tarball on a hosted, driverless, non-Tegra ARM64 runner and
     checks that the loader ignores it there;
   - deploys the combined Pages site with every artifact in
     `scripts/release/tegra-pages-retained.json`.

   The script then runs the public installed-wheel smoke and the Node smoke.
   The Node smoke installs `fathomdb@0.8.27` from npm and the tarball from
   `https://fathomadb.github.io/fathomdb/tegra/packages/fathomdb-linux-arm64-gnu-tegra-0.8.27.tgz`,
   checks its SHA-256, and repeats forced-CUDA embedding and reranking, the GPU
   witness and heap-growth checks. A skipped or failed smoke is INCOMPLETE.
4. Add the wheel and tarball entries the script prints to
   `scripts/release/tegra-pages-retained.json` in a reviewed commit, before
   any later Pages deployment, so neither deployer drops them.
5. Replace the `<0.8.27-tarball-sha256>` placeholder in
   `docs/install/typescript.md` with the published tarball SHA-256, and remove
   the "not yet published" notes for the Tegra Node package in `README.md`,
   `docs/install/typescript.md`, `docs/compatibility/index.md`,
   `docs/embedder.md`, `src/ts/npm/README.md` and
   `docs/operations/tegra-pages-publication.md`.
6. Retain the workflow URL, exact SHA, wheel and tarball SHA-256s, the
   driverless ARM64 evidence, and both Pages-smoke evidence directories.

## Troubleshoot and repair

- Treat the workflow log and its retained evidence as the oracle. Do not use
  `LD_PRELOAD`, add a dynamic `libcudart` dependency, hand-upload a wheel or
  tarball, or bypass the exact-SHA check.
- For a build/link failure, add or run a failing check in
  `scripts/tests/test_cuda_release_contract.sh` or
  `scripts/tests/test_tegra_napi_build_contract.sh`, repair the pinned Candle
  or Tegra wrapper, and prove no unresolved `cuda*` symbols, no dynamic
  CUDA/NVIDIA dependency, and a clean installed import.
- For device smoke failures, verify `nvidia-smi` exposes classic `nvgpu`, the
  offline model cache is present, and the witness is in-process. Repair the
  workflow/wrapper with a focused regression test before rerunning.
- For a driverless ARM64 import failure, read the
  `tegra-node-driverless-arm64` artifact; repair with a failing case in
  `scripts/tests/test_tegra_node_driverless_smoke.sh` first.
- For Pages failures, repair `scripts/release/build-pages-site.sh` or the
  exact-version index contract; rerun the publisher script on a new reviewed
  release-branch SHA. Do not move the tag or publish a generic artifact.
