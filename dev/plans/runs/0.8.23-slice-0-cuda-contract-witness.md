# 0.8.23 Slice 0 — CUDA contract witness

## Scope

This witness freezes the release seam before Slice 5 changes package publishing:

| Requirement | Implemented contract |
| --- | --- |
| Linux CUDA feature graph | `fathomdb-napi` forwards `embed-cuda` to the engine, and the dedicated N-API build wrapper selects that feature. |
| CPU CI boundary | Existing cross-platform `build-python` and `build-napi` stay CPU-only. |
| Trusted execution | Only a dry-run `release.yml` dispatch can run `cuda-contract-preflight` on `[self-hosted, Linux, X64, gpu, cuda-12]`. It depends on `verify-release`, which verifies the candidate is reachable from `main`. No pull-request trigger or publishing dispatch can reach that job. |
| Build/link witness | The preflight records the runner driver/toolkit plus the exact designated CUDA/manylinux image ID, and records `maturin`, Rust, CUDA, `readelf`, and `ldd` from the build context for the N-API binary and Python extension. |
| Driverless CPU proof | Two isolated, no-network containers install the built wheel and the packed main+platform N-API packages. Each mounts the pinned local model mirror read-only, selects CPU, opens with the default embedder, executes a 384-dimensional embedding, then open/write/search/close/exits without `/dev/nvidiactl`. |

The source of truth for CUDA build features is
`scripts/release/cuda-artifact-contract.sh`; the checked wrappers consume it so
the Python and N-API feature spellings cannot drift independently.

## Design review outcomes

- CUDA remains Linux x86_64-only and CPU-default. The normal platform matrix
  is deliberately unchanged; Slice 5 must wire the approved CUDA contract into
  release-equivalent artifacts and their installed-artifact smokes.
- The selected group restriction is exercised through `release.yml` at `main`
  with an immutable, main-reachable dry-run candidate. This is the selected
  main-pinned dispatch path; a tag does not need runner-group access during
  this slice.
- The exact Python probe runs `maturin build --manylinux 2_28` with CUDA
  12.6, `CUDA_COMPUTE_CAP=75`, and
  `pyo3/extension-module,embed-cuda` *inside* the designated runner's
  provisioned `fathomdb-cuda-manylinux:12.6-manylinux_2_28` image. Compute
  capability is explicit because a manylinux build cannot rely on
  `nvidia-smi`; 7.5 is the hosted T4 floor and the self-hosted RTX 3090 can run
  that target. The probe fails closed if that image, its in-container
  toolchain/toolkit, Docker access, a build artifact, the pinned local model
  mirror, or either driverless installed-artifact smoke is absent. Its dynamic
  dependency output determines the runtime-library policy; it is not inferred
  from static configuration.
- The worktree sandbox can read CUDA 12.6's compiler but cannot access Docker
  or NVIDIA devices. Therefore the designated-runner workflow artifact is the
  required completion evidence for the hardware and driverless claims; this
  document does not claim that evidence before the non-publishing dispatch.

## Remaining designated-runner evidence

Before Slice 0 can close, provision on the designated runner the
`fathomdb-cuda-manylinux:12.6-manylinux_2_28` image (CUDA 12.6, Rust,
maturin, and CPython 3.11) and its verified local Hugging Face mirror for the
pinned BGE-small revision. Then dispatch `release.yml` from trusted `main`
with `dry_run=true`, a main-reachable full candidate SHA, and a non-release
version. Retain the uploaded `cuda-preflight-witness` artifact and record its
run URL, toolkit/driver output, in-container manylinux build output, build/link
output, and both driverless installed-artifact smoke results in this witness. A
failed preflight is a release blocker; it must not be bypassed by a CPU runner
or by a tag/publish run.
