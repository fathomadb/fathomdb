# 0.8.23 Slice 1 — dependency and library-sweep disposition

## Outcome

Retain the deliberate Dependabot pause and make no dependency, lockfile,
bootstrap, hook, or CI change in this release-planning slice. There is no
verified version target from which a Library Bump Orchestrator could safely
start, and a planning record must not turn missing advisory data into an
"up-to-date" claim.

## Disposition

1. **Dependabot configuration:** retain the existing five ecosystem entries
   and their zero open-PR limits. Do not modify `.github/dependabot.yml` in
   this slice.
2. **Dependency updates:** propose none. The Library Bump Steward/LBO process
   remains the owner of any actual upgrade, which must start from a successful
   fresh registry/advisory sweep and receive its own isolated worktree.
3. **Advisories:** do not classify any advisory as fixed, acceptable, or
   non-urgent from this record. A human or integration with Dependabot-alert
   read access must review the current default-branch alerts; the historical
   note about ignored evaluation inputs does not substitute for that review.
4. **Next trigger:** after the Slice 6 preparation report, either authorize a
   dedicated dependency-maintenance slice with advisory access and functional
   registry DNS, or explicitly retain the pause with a dated manual-advisory
   review. Neither route changes 0.8.23 feature scope by itself.
