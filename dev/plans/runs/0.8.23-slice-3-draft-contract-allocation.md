# 0.8.23 Slice 3 — draft needs, requirements, and AC allocation

## Outcome

This is a draft allocation, not a CRUD edit to `dev/needs.md`,
`dev/requirements.md`, `dev/acceptance.md`, an interface contract, or an ADR.
Those existing documents remain authoritative until an owning feature is
expressly commissioned and its contract change is approved. IDs below are
temporary planning labels to avoid minting
apparently approved `REQ-*` or `AC-*` identifiers prematurely.

## Proposed CRUD after HITL approval

| Authoritative record | Proposed operation | Scope rule |
| --- | --- | --- |
| `dev/needs.md` | Create the seven approved N23 need statements, or reject/defer them individually. | Do not rewrite existing personas or historical needs. |
| `dev/requirements.md` | Create only the corresponding approved R23 requirements. | A rejected/deferred need creates no requirement. |
| `dev/acceptance.md` | Create only approved AC23 criteria, one observable assertion per criterion, with real test/fixture ownership. | Do not mint numbers, thresholds, or tests before the owning feature-slice design review. |
| `dev/interfaces/` and ADRs | Update only if the approved Slice 30 public typed outcome or another approved feature changes the contract/decision. | No interface or ADR edit is authorized by this draft alone. |
