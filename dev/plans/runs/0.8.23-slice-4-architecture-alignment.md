# 0.8.23 Slice 4 — architecture and code-alignment review

## Finding

The candidate designs name extensions to existing seams; none is evidence that
the corresponding feature is already complete. The architecture remains
consistent if the post-Slice-6 feature work stays within the following
boundaries.

| Candidate | Existing seam / alignment finding | Required design boundary |
| --- | --- | --- |
| CUDA (10/20) | `embed-cuda` already reaches the Python path; the N-API feature forwarding and release-equivalent artifact evidence are separate work. CPU vector retrieval is intentionally unchanged. | Keep Linux x86_64 and explicit device selection; do not turn a CUDA build into default GPU selection or an ANN/retrieval rewrite. |
| Embedding/Memex (30) | Deferred projections and cross-SDK bindings are the correct seams for a typed embedder-required outcome and readiness report. | One shared domain outcome must map equivalently into Rust, Python, and TypeScript; configured-worker failures remain operational errors. |
| Scale (40) | The production two-phase vector read path and AC-013 fixture are the system under test. | Extend the existing experiment artifact path; no alternate benchmark framework, mocked DB, ANN claim, or supported-scale promise. |
| Gitleaks (50) | Tracked hooks and always-on CI are the two enforceable boundaries. | Scan staged index and reachable history with redaction/fail-closed behavior; do not change release authority. |
| Windows WAL (60) | The engine deliberately returns `ErasureIncomplete` for a pinned reader after the fixed checkpoint retry budget. | Gather cross-process Windows evidence and diagnostics before any retry tuning; never weaken the fail-closed erasure contract. |

## Cross-cutting alignment

- Public-surface changes are limited to the Slice 30 outcome and any later
  explicitly approved documentation; they require interface-doc/ADR review in
  the owning feature slice.
- Schema version, identity/provenance, migration, and CPU-default contracts are
  untouched by Slices 10–60 unless a separately scoped design says otherwise.
- The local Windows guest is a controlled reproduction environment, not CI or
  release evidence. The protected CUDA runner is a release gate, not general
  CI capacity.
- No architecture/code discrepancy authorizes an implementation in this
  planning review. The only required action is to preserve these boundaries in
  the Slice 6 package and in each approved feature design review.
