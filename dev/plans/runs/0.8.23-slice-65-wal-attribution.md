## Fix-N — runtime ownership and truthful retained-result RED

Independent review found two gaps in the original design. A projection
dispatcher and every projection worker own runtime SQLite connections, so they
must report role-local index plus transaction/snapshot transitions. A busy
attempt cannot be `no_owned_snapshot` until those roles as well as every reader
worker are idle and there is no local checkpoint overlap. The collector records
`owned_runtime_transaction` separately from an owned reader snapshot.

The retained-result control now has the correct production expectation: a
materialized Python result retained after its call returns, with a live but idle
Engine, has zero owned transaction/snapshot and `erase_source` succeeds. Its
RED is the absence or misclassification of that required collector fact before
GREEN instrumentation, never a fabricated expectation that retention itself
causes `BUSY`.

## Implementation record — pending first-party Windows evidence

`0583a323` implements the approved diagnostic scope only; `a5254b83` and
`ae3b4b00` are Fix-Ns for reviewer-found lifecycle and evidence gaps. A private collector
is disabled unless controlled CI sets `FATHOMDB_WAL_ATTRIBUTION=1`; it emits

a busy checkpoint in that state has the internal `unclassified_external` code,
whose outcome is **unattributed** rather than blamed on Windows, an external

its deferred transaction has selected and acquired a WAL snapshot. It parses
the collector's retained records, requiring all five busy attempts to name the
exact paused `reader_worker:0` as `owned_reader_snapshot`, then requiring the
post-release success to record `no_owned_snapshot`. Normal reader transitions
now begin only after actual `BEGIN DEFERRED` plus the collector-only snapshot
read; dispatcher and worker transitions begin at their actual SQLite statement
and `BEGIN IMMEDIATE` boundaries. The reader pause seam is crate-private, so
it is unavailable in published Rust artifacts. The retained Windows job runs
this record-parsing managed-reader control alongside the Slice 60
external-child control, with a nonsecret artifact and a load-bearing workflow
mutation test. Its exact lib-test filter is fully qualified, and the job scans
the retained output for `running 1 test` before it may continue; zero selected
tests are a failure. The normal reader probe is
`SELECT COUNT(*) FROM canonical_nodes`, not `SELECT 1`, so it establishes a
database/WAL snapshot before the collector labels it acquired.
