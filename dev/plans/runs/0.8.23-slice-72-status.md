# Slice 72 — concurrent embedding and CE GPU coexistence

## Landed local implementation

`77c460c9..687f779c` is integrated on the local `release/0.8.23` branch.
It adds a feature-gated, test-only real-engine characterization harness for
one process that uses independently selected CUDA embedding and TinyBERT CE
reranking on the same process-visible device. It does not add a GPU scheduler,
reservation, memory cap, or public telemetry API.

The harness preflights immutable BGE and TinyBERT caches before engine open,
requires exactly one process-visible selected CUDA device for each model, and
uses the resolver UUID as telemetry authority. Its basic and bounded
low/moderate tiers are designed to assert real BGE and CE forward overlap when
run on an authorized CUDA runner; its ignored stress tier is authenticated to a
parent watchdog, has a hard 120-second child-process bound, and retains timeout
evidence. Receipts distinguish process CPU/RSS from
device-wide GPU utilization and VRAM, bind compute-app PID evidence, retain
sensor provenance, and fail closed on malformed, wrong-device, missing, or
out-of-order evidence.

The range contains committed RED-to-GREEN increments, including review-driven
contracts for cache preflight, receipt schema, active-overlap sampling, stress
containment, and failure evidence. Independent design review, code review,
verification, and semantic public/project/developer documentation review
passed. Focused deterministic tests, `agent-verify`, workspace check/clippy,
markdown/documentation lint, and strict MkDocs passed.

The TC-5 decision is **no Slice 72 GPU path**: its private vector-stage
workload is pre-fusion and rejects CE; the external TC-5 execution contract
remains CPU-only pending a separate amendment. SQLite bit-KNN, exact-f32
database reranking, FTS, fusion, graph, and storage remain CPU work.

## Pending external release closure

No trusted NVIDIA runner was available locally. `nvcc` is absent and
`nvidia-smi` cannot communicate with an NVIDIA driver, so the CUDA hardware
target could neither compile nor run. Consequently there is no retained GPU
characterization receipt or performance claim. The real basic, low/moderate,
and explicit stress tiers remain `PENDING_EXTERNAL`; the local implementation
and all deterministic evidence are complete. No dispatch, tag, push, registry
operation, or publication occurred.
