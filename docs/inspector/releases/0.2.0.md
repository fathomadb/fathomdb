archive and directly usable bundle are at `dist/inspector/0.2.0/` in the dedicated

## Support and limitations

The qualified pairing is Ubuntu 22.04/glibc 2.35 Linux x86_64 userland with
kernel 7.0.0-43-generic/Landlock ABI 8 and Chromium 156.0.8078.4. Cached CPU needs
Landlock ABI >=3; stock Ubuntu 22/kernel 5.15 is insufficient. Selected Engine source
is0.8.29 commit `6edc1155f039f87cd0a37660cb27ae4373bbce71`, schema 37.
No broader browser/OS/SDK compatibility follows from that pairing. Model assets
are existing pinned cache prerequisites; they are not bundled/downloaded/repaired.

External writers must be stopped. Normal owned Engine lifecycle/background work
can change files. No editing/admin, migration/recovery, immutable forensic view,
live-application attachment, multiple vector source windows, saved workspace,
general export, GPU or additional-platform support is included. Disclosure flags,
physical deletion, resource bounds and unknown evidence stay binding.
The former five-person study was removed by owner decision; no sessions occurred.

## Future distribution methods

A public archive/GitHub Release is the closest future extension of the tar method.
An Inspector-only crates.io source package or OS package channel is a separate
option, with its own installation and dependency qualification. npm/PyPI are not
current Inspector runtimes or distribution promises. Before any public channel,
define Inspector-specific version/tag naming, supported build CI and ABI matrix,
registry ownership/credentials, license notices, checksum/signing/provenance and
upgrade/removal tests. Do not use the repository's Engine `v*` publication tags.
0.2.0 implements no uploader and requests no registry credentials.
