# Inspector 0.2.1 release notes

Inspector 0.2.1 was released locally on 2026-11-21 for Linux x86_64. The
complete archive and directly usable bundle are at `dist/inspector/0.2.1/` in
the dedicated `inspector/dev/0.2.1` release checkout. Slice 30 promoted the
exact qualified candidate atomically; `dist/inspector/0.2.0/` remains
untouched. No registry deployment, public download or human-study validation is
claimed. [Installation](../getting-started/index.md) requires only the extracted
application, graphical Chromium and the declared OS/kernel prerequisites.

## Changes from Inspector 0.2.0

- **FathomDB 0.8.30 Engine integration:** Rebased onto `release/0.8.30`
  (`72fe93634321616214352a7e07066ce0f93bcf4c`, byte-identical Rust/Cargo source
  to `v0.8.30` `e3d31f5cdc0df3e32dab9bad151c5ab5c321222c`), compiled schema 37,
  with Candle `0.13.0`, cudarc `0.21.0`, Tokio `1.54.1` and `webpki-roots`
  `1.0.12`. Zero modifications to `src/rust/` or `.cargo/config.toml`.
- **Record-keyed lexical retrieval metadata & UI copy:** Updated body and
  property lexical origin metadata to `"record_keyed_not_merged"` (retaining
  `"not_inferred"` on BM25F) and UI labels from `Equal-body contributors:` to
  `Record identity:`, reflecting 0.8.30 record-keyed fusion across equal-body
  nodes, edges and retained revisions.
- **0.8.30 behavior & regression coverage:** Added end-to-end real-Engine
  coverage for `embedder_absent` and `embedder_timeout` degradations through
  `Reader::serving`, `Closing` propagation, ownerless FTS withholding vs
  diverged node/edge `body` and `kind` refusal, whole-body and partial UTF-8
  provenance spans (and negative digest/offset/empty boundaries), and open-time
  `_fathomdb_vector_spans` validation.
- **Native Ubuntu 24.04 build & qualification (Docker removed):** Dropped Ubuntu
  22.04 (`glibc 2.35`), Docker, `openbox` and `xdotool`. Packaging and
  installed qualification run natively on Ubuntu 24.04 (`glibc 2.39`) under
  `Xvfb`, `/proc` process discovery, CDP `Browser.close` and parent-wrapped
  `strace -ff`.
- **Dual published producer qualification:** Qualified freshly extracted final
  `dist/inspector/0.2.1/` bytes against fresh closed real databases produced by
  both published PyPI `fathomdb==0.8.29` and published PyPI `fathomdb==0.8.30`.

## Support and limitations

The qualified pairing is Ubuntu 24.04 / glibc 2.39 Linux x86_64 userland with
kernel `7.0.0-43-generic` / Landlock ABI 8 (minimum ABI 3) and Chromium
`156.0.8078.4`. The native executable requires at most GLIBC 2.39; Ubuntu 22.04
/ glibc 2.35 is no longer supported. Selected Engine source is `0.8.30` commit
`72fe93634321616214352a7e07066ce0f93bcf4c` (schema 37), qualified against
closed databases produced by published FathomDB `0.8.29` and `0.8.30`. No
broader browser/OS/SDK compatibility follows from that pairing. Model assets
are existing pinned cache prerequisites (`BAAI/bge-small-en-v1.5` revision
`5c38ec7c405ec4b44b94cc5a9bb96e735b38267a`); they are not bundled, downloaded
or repaired.

External writers must be stopped. Normal owned Engine lifecycle/background work
can change files. No editing/admin, migration/recovery, immutable forensic view,
live-application attachment, multiple vector source windows, saved workspace,
general export, GPU or additional-platform support is included. Disclosure flags,
physical deletion, resource bounds and unknown evidence stay binding.
The former five-person study remains removed by owner decision; no human
sessions occurred.

## Future distribution methods

A public archive/GitHub Release is the closest future extension of the tar
method. An Inspector-only crates.io source package or OS package channel is a
separate option, with its own installation and dependency qualification.
npm/PyPI are not current Inspector runtimes or distribution promises. Before
any public channel, define Inspector-specific version/tag naming, supported
build CI and ABI matrix, registry ownership/credentials, license notices,
checksum/signing/provenance and upgrade/removal tests. Do not use the
repository's Engine `v*` publication tags. 0.2.1 implements no uploader and
requests no registry credentials.

For historical `0.2.0` (Engine `0.8.29` / Ubuntu 22.04) details, see the
[0.2.0 release notes](0.2.0.md).
