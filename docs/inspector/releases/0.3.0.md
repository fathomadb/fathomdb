# Inspector 0.3.0 release notes

Inspector 0.3.0 targets FathomDB 0.8.31 (compiled schema 38) for Linux x86_64
under the retained `D4 = B` native Ubuntu 24.04 (`glibc 2.39`) Chromium +
bundled SQLite qualification stack. Release builds are produced by the
`build-inspector` job in `.github/workflows/release.yml`, which checks ELF
`GLIBC <= 2.39`, seals and verifies the candidate, and attaches
`fathomdb-inspector-0.3.0-linux-x86_64.tar.gz` and
`fathomdb-inspector-0.3.0-linux-x86_64.tar.gz.sha256` to the FathomDB GitHub
Release. Local candidate verification and atomic promotion remain available via
`src/inspector/tools/local-release.py`. No human-study validation is claimed.
[Installation](../getting-started/index.md) requires only the extracted
application, graphical Chromium, and the declared OS/kernel prerequisites.

## Changes from Inspector 0.2.1

- **FathomDB 0.8.31 / Schema 38 strict admission & reserved `scope`:** Admits
  Schema `38` databases (`compiled_schema = 38`), rejects Schema `37`
  (`0.8.30`) and older or missing-layout stores cleanly without mutating files,
  validates `properties` and `scope` columns plus `_fathomdb_projection_registry.{entity_class,vector_kinds}`,
  `canonical_property_values`, `_fathomdb_commit_timestamps`, and
  `_fathomdb_vector_kinds`, and displays reserved `scope` read-only (empty in
  `0.8.31`; multi-tenant scope enforcement belongs to `0.8.32`).
- **Outside-`body` node & edge `properties` UI + XSS & erasure safety:**
  Inspect, expand (`detail_field`, `chunk`, `tree` with explicit `field`
  threading across `drawTree()`), and copy outside-`body` node and edge
  `properties` alongside plain-text or JSON `body` documents while preserving
  exact 64-bit integer lexemes outside `2^53`, `-0`, empty strings, typed
  primitives, and `SQL NULL`. All user and database keys, values, and `scope`
  render strictly via DOM `.textContent` (inert against HTML/SVG/script
  injection). `"properties"` participates in 64 MiB graph/lexical memory
  admission scans, `associations` and `catalog` cover bounded
  `canonical_property_values` across both nodes and edges (filtering edge-only
  declarations out of node-only lexical property choices), and all 8 `D-01`
  policy flag combinations withhold `properties`, `properties_bytes`, and
  `typeof(properties)` whenever `!policy.permits(class)`.
- **Historical `as_of` graph exploration & 8-flag subordination:** Stored
  (`graph`) and native engine (`graph_serving` via
  `GraphExpandRequestV1::with_as_of_{write_cursor,epoch_ms}`) graph views accept
  mutually exclusive `as_of_write_cursor` or `as_of_epoch_ms` (`Option<String>`
  wire encoding resolved via O(log N) reverse seek over
  `_fathomdb_commit_timestamps`). Historical mode lifts
  `INDEXED BY canonical_nodes_logical_active_idx` using two-branch `UNION ALL`
  over Schema 38's `canonical_nodes_logical_{active,sup}_idx` while current
  mode keeps non-partial `canonical_edges_{from_id,to_id}_idx` when
  `!no_show_inactive`. Invalid inputs fail locally without evicting UI cache,
  `Back` and A/B comparison pins retain exact `as_of` context, and every
  historical target, edge, origin, and inline property payload obeys all 8
  `D-01` disclosure flags.
- **Scoped local CI (`local-ci.sh --scoped`) & bounded timeouts (`P7-02`):**
  `src/inspector/tools/local-ci.sh` defaults to `--scoped` (~5 min
  Inspector-scoped source check with fail-closed diff guard against `--base` /
  `INSPECTOR_SCOPED_BASE`) while retaining mutually exclusive
  `--full-workspace` and `--installed-only` modes. Subprocess, `Xvfb`,
  `strace`, Playwright `browser.close()`, and Rust `launch.rs` harnesses
  enforce bounded timeouts with `SIGKILL` escalation and `/proc` descendant
  reaping.
- **GitHub Release artifact delivery (`build-inspector`):**
  `.github/workflows/release.yml` adds `build-inspector` on `ubuntu-24.04`
  (gated by `all-builds-passed`, attached by `github-release`) delivering
  `fathomdb-inspector-0.3.0-linux-x86_64.tar.gz` and
  `fathomdb-inspector-0.3.0-linux-x86_64.tar.gz.sha256`, while retaining
  `D4 = B` Docker-free Ubuntu 24.04 (`glibc 2.39`) qualification.

## Artifact verification

From a GitHub Release download directory:

```sh
sha256sum --check fathomdb-inspector-0.3.0-linux-x86_64.tar.gz.sha256
mkdir inspector-install
tar -xzf fathomdb-inspector-0.3.0-linux-x86_64.tar.gz -C inspector-install
cd inspector-install/fathomdb-inspector-0.3.0-linux-x86_64
sha256sum --check SHA256SUMS
./fathomdb-inspector --build-description
```

Local candidate builds produced by `src/inspector/tools/package.sh` and sealed
with `src/inspector/tools/local-release.py seal` also include outer
`SHA256SUMS` and unsigned `candidate.json` provenance binding archive and
executable digests to the clean packaging commit, workspace engine version,
compiled schema (`38`), and `D4 = B` support metadata.

## Support and limitations

The qualified pairing is `D4 = B` Ubuntu 24.04 / glibc 2.39 Linux x86_64
userland (bundled SQLite, zero GTK4/WebKitGTK or Docker requirements) with
kernel `7.0.0-43-generic` / Landlock ABI 8 (minimum ABI 3) and Chromium
`156.0.8078.4`. The native executable requires at most GLIBC 2.39; Ubuntu 22.04
/ glibc 2.35 is not supported. Inspector `0.3.0` compiles Schema `38` for
FathomDB `0.8.31` and refuses Schema `37` (`0.8.30`) and older formats cleanly.
No broader browser/OS/SDK compatibility follows from that pairing. Model assets
are existing pinned cache prerequisites (`BAAI/bge-small-en-v1.5` revision
`5c38ec7c405ec4b44b94cc5a9bb96e735b38267a`); they are not bundled, downloaded,
or repaired.

External writers must be stopped. Normal owned Engine lifecycle/background work
can change files. No editing/admin, migration/recovery, immutable forensic view,
live-application attachment, multiple vector source windows, saved workspace,
general export, GPU, or additional-platform support is included. Disclosure
flags, physical deletion, resource bounds, and unknown evidence stay binding.
The former five-person study remains removed by owner decision; no human
sessions occurred.

For earlier releases, see the [0.2.1 release notes](0.2.1.md) (FathomDB 0.8.30
/ Schema 37) and [0.2.0 release notes](0.2.0.md) (FathomDB 0.8.29 / Ubuntu
22.04).
