# FathomDB 0.8.28

Documentation targets 0.8.28; publication is pending. Candidate tests do not
establish registry or Pages availability. The [changelog](https://github.com/fathomadb/fathomdb/blob/release/0.8.28/CHANGELOG.md)
has the full change and removal list.

## Retrieval and application APIs

- Direct node/edge body FTS accepts SearchFilter across Rust, Python and
  TypeScript, applied before candidate caps, deduplication, ranking and limit.
  Attributes are node-scoped. Status/time need stored vector metadata; status
  has an empty-string sentinel and time is inclusive projection time.
- Independent include-superseded/include-inactive search flags preserve validity,
  dependency and edge-expiry rules. Historical property filters use canonical
  rows; incomplete dense history uses lexical fallback.
- Native vec0 lifecycle/validity metadata replaces the whole-store eligibility
  scan before KNN caps. Lexical query/ranking and bounded pending-work fixes
  retain their documented limits.
- Context pack, role-tagged round bodies, full-item overrides and open-time
  stop words are available across the three SDKs. Context rendering is stateless;
  item-text budgets count Unicode scalars and exclude headers/separators.

See [filtering](../guides/hybrid-search-filtering.md),
[context packing](../guides/prompt-context.md) and [configuration](../reference/config.md).
MCP server exposure, including this filtered body FTS, belongs to planned 0.8.29.

## Storage, provider admission and maintenance

Current fresh-store format is **36**. Format35's 64-row vec0 chunks, cursor-keyed
FTS and UTF-8 head coverage are retained; format36 adds persisted maintenance
policy, queue and fence metadata. Older formats are refused without migration.
Finish/export old stores with the matching old product, then re-ingest into a
fresh store. Head coverage is metadata, not chunked retrieval.

Production engines accept the pinned built-in provider or none. Caller-provider
injection is removed. Numerical mismatch and inability to verify are distinct
open errors returning no Engine; dense-disabled report fields/modes are removed.
Persistent acceptance caching retains its backend-drift limitation. Deliberate
no-provider access is mutable canonical/text access, not verification or certified
dense repair; no-provider dense rebuild has a known limitation.

Explicit maintenance is opt-in and persisted. Queueing leaves logical visibility
unchanged; an owned window excludes ordinary work during activation/cleanup.
Incomplete activated debt retains durable write fences and original-sink/WAL
requirements. No immediate revocation or completion deadline is promised.
See [erasure](../operations/erasure.md#schedule-an-explicit-maintenance-window)
and [typed errors](../reference/errors.md).

## Dependencies and platforms

The SQLite stack is `rusqlite` 0.41.1 / `libsqlite3-sys` 0.39.1 (SQLite 3.54.1)
with per-connection page caches, replacing the vendored SQLite crate. CUDA uses
qualified published `cudarc-fathomdb` 0.19.10 and Candle fork 0.11.0 dependencies;
the existing Candle-kernels git patch/linkage boundary remains explicit.

CUDA builds on AArch64 include the private Tegra pool; qualified AGX Orin builds
use it, while generic ARM64 native artifacts remain CPU-only. CUDA import/fork,
loaded-library and pool-setting limits remain in the
[embedder guide](../embedder.md). Supported CPU/native targets and exact runtime
pins are in [compatibility](../compatibility/index.md). Existing performance
measurements are workload-specific evidence, not general SLAs or new platform
qualification. Final candidate CI/platform/release rehearsal belongs to Slice 95.
