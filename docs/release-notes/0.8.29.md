# FathomDB 0.8.29 (in progress)

MCP results now default to compact text: one text block, with no
structuredContent or outputSchema. Operators with structured consumers must
set `"result_format": "structured"` in MCP JSON configuration. That mode retains
schemas and typed fields and sends the exact final JSON payload in its text
block. Invalid formats fail configuration validation.

Compact output preserves quoted metadata, degradation, explanations, hints and
budget signals. Search/expand have one line per hit; fetch uses raw UTF-8
byte-length body frames. Scores display three decimals while structured scores
remain unchanged. Final budgeting counts the selected representation, including
its own count and, for structured mode, both JSON copies. Tiny budgets may
return a truthful zero-progress cut page or a typed refusal; complete traversal
requires enough budget for a whole leading hit.

Direct MCP text search now forwards kind, source_type, status, created_after
and declared filterable attribute equalities through the provider-free SDK
route before candidate caps and ranking. Attributes remain node-scoped;
status/time require existing projected metadata. Both search modes now accept
`include_superseded` and `include_inactive` independently or together, defaulting
to false. Supplied flags must be booleans; null is invalid. They compose with
filters and the selected validity instant, preserving node windows and mandatory
edge expiry. Continuations retain the original view and reject supplied flag
overrides, including false or null. Repeated historical refs remain separate
results; logical fetch still resolves the latest eligible revision under its
own view. Final integrated release qualification remains pending.

Selected changes still awaiting implementation: fusion will identify the same
stored record/version across arms and retain distinct versions/sources even with
equal bodies, preserving vector/text/graph representative-first provenance.
Public IDs and `context_item_from_hit` ID derivation stay unchanged;
`pack_context` retains duplicate-ID refusal. Callers can supply unique packing
labels and keep their own label-to-record map.

The selected .29 feedback correction will atomically refuse ambiguous named refs
on otherwise-recordable calls, preserve existing `not_recorded` precedence, and
write no partial labels. Richer precise per-result feedback is a .30 review
follow-up. These identity/feedback selections are planned, not shipped behavior.
Logical fetch retains its latest-eligible-view semantics.

Store schema remains37. No migration is introduced.
