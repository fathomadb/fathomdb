# FathomDB 0.8.29

Published 2026-11-18. [GitHub Release](https://github.com/fathomadb/fathomdb/releases/tag/v0.8.29).

FathomDB remains pre-1.0 beta. This release improves record identity in
retrieval, exposes exact stored-head coverage, and updates the MCP response
contract. The [changelog](https://github.com/fathomadb/fathomdb/blob/release/0.8.29/CHANGELOG.md)
records the complete changes and compatibility limits.

## Stored-head coverage and snippets

Projection runtime status now requires stored mapped-head coverage:
`vector_coverage` in Rust/Python and `vectorCoverage` in TypeScript. It reports
known, unknown and truncated record counts, known/unrepresented byte totals,
and exact unreduced known-only fractions. The population includes retained
mapped history; it does not describe current-view eligibility or physical
vector health. Unavailable results name `cache_cold` or `state_changed` and
carry no numeric facts. Ordinary status reads do not force a corpus scan or
refresh.

Python retains exact integers. TypeScript and MCP aggregate counts, byte totals
and fraction components use decimal strings; the stored profile dimension
remains numeric. See the [Python](../reference/python-api.md#stored-head-reporting),
[TypeScript](../reference/typescript-api.md#stored-head-reporting) and
[Rust SDK](../reference/rust-sdk.md#stored-head-reporting) references.

An opt-in snippet's `scored_bytes` / `scoredBytes` is the original contributing
stored head extent of that exact vector participant. Zero is known empty;
absence makes no extent claim. Coordinates include stored role-marker bytes.
Text-only search and standalone snippet selection do not acquire an extent.

## Retrieval and degradation

Hybrid fusion identifies each stored record/version across arms. Equal bodies
or public references no longer merge distinct records, and one record contributes
once per arm at its original rank. Ranking, snippets, explanations and evidence
retain the selected record's ownership and UTF-8 byte coordinates.
`pack_context` / `packContext` still refuses duplicate item IDs; callers can
assign distinct packing labels and retain their own label-to-record map.

Search and expansion report bounded query-embedding absence, started timeout
and overload reasons consistently. An empty degradation report does not prove
that every arm ran. Typed CUDA failures remain errors.

## MCP consumers

MCP results default to compact text: one text block, without `structuredContent`
or `outputSchema`. Structured consumers must set `"result_format": "structured"`
in the MCP JSON configuration. This retains typed fields and schemas and places
the exact final JSON payload in the text block.

Final serialized output, including metadata and hints, counts toward the response
budget. Continuation cuts retain whole hits. Tiny budgets may produce a truthful
zero-progress cut or typed refusal; increase the budget enough for a whole
leading hit before restarting traversal.

Text and hybrid search accept the closed filters and independent
`include_inactive` / `include_superseded` flags, both defaulting to false.
Continuations retain the original view. Ambiguous named feedback references are
refused atomically. Corrective details for `unknown_argument` and
`refs_not_in_response` include bounded original details, accepted argument names
and remedies; rejected feedback writes no labels. `list_stores` exposes an
explicit nullable `default_store`.

Successful responses remove the unavailable-only envelope `state` and search
`verdict` fields. `orient.not_in_this_release` identifies unavailable state,
verdict, kinds and counts; structured kinds/counts placeholders retain their
existing contract. Rust projection-status and snippet structs gain fields, so
exhaustive literals and patterns must be updated.

## Format and delivery boundaries

Store format remains **37**, as in 0.8.28. Public opens create a fresh schema-37
database or accept an already-current one; there is no automatic migration.

Generic Python and Node packages target Linux x86_64/glibc, Linux AArch64/glibc,
macOS x64/arm64 and Windows x64. Generic AArch64 packages are CPU-only.
**No 0.8.29 Tegra CUDA wheel or Node addon is provided.** The published 0.8.28
Python `+tegra` wheel and matched 0.8.28 Node main/addon pair remain available
through the retained [Python](../install/python.md#jetson-tegra-cuda) and
[Node](../install/typescript.md#classic-jetson-orin-with-cuda) routes. Never
combine a 0.8.29 main package with the 0.8.28 addon. With no Tegra addon installed,
the Node loader uses the generic CPU package; a mismatch on a confirmed classic
Jetson Orin is refused before native loading.

The selected CUDA dependency updates add lifetime tracking and private F32
upload fixes. Detected terminal context loss refuses further CUDA construction,
embedding and cached reranking until process restart. Native residue may remain
until restart, and opaque native host memory has no established hard bound.
Live-reset survival and post-reset close/exit remain unqualified. Current CUDA
qualification uses CUDA 12.6; local Rust/CUDA results do not establish prebuilt
Tegra availability. CUDA 13 artifact delivery, including Tegra, is planned for
0.8.31. Non-Tegra ARM+GPU configurations remain outside the known-working CUDA
set and the 0.8.29 qualification scope.

Recovery verification covers additional process interruption, active-checkpoint
retry/reopen and Windows WAL scenarios; it does not establish power-loss or
exhaustive fault coverage. All required crate, PyPI and npm publishers and eight fresh registry-installed
consumer jobs pass, including Python, Node, Rust SDK and CLI consumers across
the five supported native targets. Original qualification failures, scoped
recoveries and the HITL-reviewed score observation remain in the release record.
