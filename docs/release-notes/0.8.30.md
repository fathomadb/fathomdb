# FathomDB 0.8.30

Source release documentation. Registry and Tegra Pages publication are pending;
this page does not declare release readiness or public artifact delivery.
The [changelog](https://github.com/fathomadb/fathomdb/blob/release/0.8.30/CHANGELOG.md)
records the release changes. Earlier published releases retain their own notes.

## Model lifetime

Python/Rust SDK `release_models()` and TypeScript `await releaseModels()`
explicitly release cached standalone CLS and cross-encoder models. Concurrent
loading, cache waits, inference or another release refuses immediately with the
existing overload category and clears neither cache. Healthy later calls can
reload. Engine-owned Mean providers remain attached to their engines. Empty or
repeated release constructs no models and does not initialize CUDA.
See [examples and concurrency](../embedder.md#release-module-models).

Terminal CUDA generation loss remains terminal until process restart. Selected
completed-construction loss and teardown cases now have exact-pin proof; reset
during inference, same-process recovery, and reclamation of lost native residue
are not promised. The qualified cudarc/Candle/kernel fork update retains PTX0
producer policy, F32 and the CUDA 12.6 support scope.

## Retrieval and provenance correctness

The optimized node-only hybrid path applies eligibility to matched rows before
cap/ranking, avoiding a whole canonical-node eligibility scan. Fusion preserves
stored record/version ownership, original rank positions and representative
provenance. Equal bodies and equal public IDs do not merge distinct records.

MCP response identity binds ordered kept ref/cursor pairs, retaining feedback
attribution when a later query returns a replacement under the same public ref.
Ambiguous named refs still refuse the whole feedback call before label writes;
logical fetch continues to select its own latest eligible revision.

Dependency tracing validates partial UTF-8 locators independently while
checking the canonical whole-source digest, fixing missing or incorrect
relationships for valid partial spans in both directions. Trace still refuses
empty ranges even though writing/registration can accept them. This fix does
not add revision/span provenance to legacy extractor ingest or expand its dense
kind vocabulary; see [extractor limits](../guides/extractor-provenance.md).

Bounded graph query seeding remains eligible canonical-body FTS ordered by
BM25/cursor, followed by a separate walk. No first-class namespace, new fused-hit
graph seed mode or entity resolution is added. See [graph modes](../guides/graph-retrieval.md).

## Installation and operations

Workspace packages use **0.8.30**; `fathomdb-embedder-api` stays **0.8.0**.
Schema remains **37**: public open accepts current nonempty stores or creates
fresh stores; there is no automatic migration. Native target and glibc floors
are documented in [compatibility](../compatibility/index.md).

The Node contract is **25.x and 26.x** (`>=25 <27`), with target-native installed
qualification on all five generic targets. Development Node 26.13.1/npm 11.20.0,
held producer Node 25.9.0/npm 11.12.1 and OIDC promotion npm 11.21.0 have separate
roles. Published 0.8.29 retains its Node 25-only contract.

Generic ARM64 artifacts remain CPU-only. Classic Orin CUDA uses the separately
published, exact-version Tegra wheel/Node pair; require its retained manifest
entries and digests before installation. CUDA 13 and additional ARM+GPU hardware
support are outside this release.

Contributor setup uses checkout-owned environments and a noneditable native
Python wheel. Scoped documentation verification stays separate from the full
source gate. Cancellation retains completed/unrun suites and redacted failure
diagnostics; registry consumers verify persisted records across process exits.
TLS roots, Tokio, Markdown tooling and the Mermaid renderer receive security
updates, with actual browser rendering and sanitizer checks for the renderer.

## Qualification limits

Tests compose real record/provenance/vector identity, temporal eligibility,
graph, process-kill/WAL recovery, persistent faults, doctor effects and SDK/MCP
boundaries. The bounded Proptest input cases are not broad coverage-guided
fuzzing, FFI fuzzing or numerical line/MC/DC coverage. Power-loss and broad
coverage-guided proof remain 0.8.31 backlog. See [operational limits](../operations/index.md#concurrency-and-durability-limits).

The matched 100k CPU study measured a 24.76% median paired warm-p50 hybrid reduction and 37.27% in its
interleaved-write schedule. Those workloads and their host
conditions are the scope, not a universal speedup guarantee. The Orin TC5
0.958 recall@10 (95% CI 0.938–0.974) is exact-f32 vector fidelity, not answer
relevance. The ten-minute Node 25 ON/OFF memory comparison is bounded diagnostic
evidence; its original protocol remains UNMEASURED and establishes no general
shipping plateau. Original failures and scoped recoveries remain in the
[release qualification records](https://github.com/fathomadb/fathomdb/blob/release/0.8.30/dev/plans/0.8.30/features/slice-70/status.md).
