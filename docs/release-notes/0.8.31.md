# FathomDB 0.8.31 (Pre-Publication Qualification)

**Pre-publication qualification notes — `0.8.31` is not yet published; registry
publication awaits Slice 80 authorization.**

These notes describe the `0.8.31` release candidate undergoing final
qualification on `release/0.8.31`. No `v0.8.31` git tag or registry upload
(crates.io, PyPI `fathomdb` and `fathomdb-cli`, npm, GitHub Pages, or GitHub
Releases) has been executed yet. The
[changelog](https://github.com/fathomadb/fathomdb/blob/release/0.8.31/CHANGELOG.md)
tracks the full change summary, and earlier releases retain their own notes.

## Schema 38, inline properties, and declared indexes

Schema version bumps from **37** to **38**. Canonical nodes and edges gain
first-class inline typed `properties` (`String`, `Int` with full `i64`
precision, `Float`, and `Bool`) stored outside the plain-text `body`, allowing
O(1) property reads without parsing JSON out of `body`. Existing rows upgraded
from schema 37 carry `properties = NULL`.

- **Declared `canonical_property_values` B-tree indexes:** `ProjectionSpec`
  adds `entity_class` (`"node"` or `"edge"`) so `Filterable` node and edge
  properties project into `canonical_property_values` (and pre-KNN `vec0`
  `attr_<hex>` slots for nodes). `SearchFilter.property_predicates` evaluates
  typed comparisons (`eq`, `ne`, `lt`, `lte`, `gt`, `gte`) against declared
  indexed properties.
- **Commit timestamps (`_fathomdb_commit_timestamps`):** Every Schema 38 write
  batch records a monotonic `(write_cursor, committed_at_ms)` pair enabling
  wall-clock historical graph lookups alongside exact cursor lookups.
- **Explicit opt-in custom vector kinds:** `ProjectionSpec.vector_kinds`
  enrolls custom node kinds in `_fathomdb_vector_kinds` (`DurableAuthority`) for
  vector indexing while keeping unenrolled custom kinds reported in
  `vector_unsupported_kinds`.
- **Operational collection readback and kind-conflict refusal:**
  `read.operational_collections` and `read.operational_collection` expose
  registered operational collections (`latest_state` and `append_only_log`),
  returning `None` / `null` when a collection is absent, while conflicting
  `kind` re-registration via `admin.configure` fails with a typed
  `WriteValidation` refusal.
- **Physical erasure fixes:** Hardens erasure across inline properties,
  `canonical_property_values`, custom-kind vector rows, and operational state
  while preserving `ROW_OWNED_PROJECTIONS` byte accounting and read-visibility
  invariants. See [erasure](../operations/erasure.md).

## Strict write endpoints and typed graph traversal

- **Strict-only write endpoint integrity:** Canonical edge writes validate that
  both `from` and `to` endpoints reference existing canonical nodes before
  committing, removing dangling-endpoint ambiguity at write time.
- **Typed traversal predicates:** `GraphExpandRequestV1` supports
  `edge_predicates` and `target_predicates` pushed down to SQLite indexes, plus
  `t_valid` / `t_invalid` valid-time boundaries and mixed-edge slot handling.
- **Opt-in `graph_seed` and provenance:** Hybrid `search()` supports explicit
  opt-in graph seeding (`graph_seed`: `"graph_fts"`, `"fused_top_k"`, or
  `"both"`) with single-pass cross-encoder reuse and per-hit graph seed source
  provenance (`"fused_top_k"`, `"edge_fts"`, `"entity_fts"`). See
  [graph retrieval](../guides/graph-retrieval.md).

## Bitemporal historical graph and frozen evidence

- **Historical `graph.expand` (`as_of_write_cursor` / `as_of_epoch_ms`):**
  Callers can reconstruct historical graph topology at an exact write cursor or
  wall-clock epoch millisecond boundary using composite indexes
  (`canonical_edges_{from,to}_sup_kind_idx`), supporting both empty and filtered
  `edge_kinds`.
- **Historical frozen evidence:** Frozen graph evidence preflight and resolution
  honor historical `as_of` boundaries and revocation invariants. See
  [frozen evidence](../guides/frozen-evidence.md).

## SDK ergonomics, `fathomdb migrate`, and `fathomdb-cli` wheel

- **Batch evidence resolution (`resolve_evidence_many`):** Resolves multiple
  frozen evidence references in a single governed SDK call across Rust, Python,
  and TypeScript.
- **Opt-in `search(hints=...)` and `OpenReport` capability booleans:** Adds
  governed `search_hints` / `hints` support and explicit `OpenReport` capability
  booleans across all three SDK bindings (56 live governed operations). See the
  [SDK operation map](../generated/sdk-operation-map.md).
- **Narrow operator upgrade (`fathomdb migrate`):** Adds a third operator CLI
  root `fathomdb migrate --backup-dir <dir> [--json] <db_path>` for explicit
  offline `37 -> 38` store upgrades with pre-upgrade SHA-256 backup verification.
  `Engine.open` remains strictly schema-38-only with no public automatic
  migration. See [CLI reference](../reference/cli.md).
- **Companion `fathomdb-cli` PyPI wheel:** Distributes the operator `fathomdb`
  binary via a separate lockstep `fathomdb-cli` package (installable via
  `fathomdb[cli]`) while keeping the `fathomdb` SDK wheel's `[project.scripts]`
  empty (`AC-041`).

## FathomDB Inspector 0.3.0

Inspector `0.3.0` integrates directly into the workspace and supports Schema 38
inspection, erasure-gated inline `properties`, historical `as_of` graph
navigation, and native release-asset packaging via the `build-inspector` release
workflow job. See [Inspector 0.3.0 release notes](../inspector/releases/0.3.0.md).

## Platform, CUDA, and qualification scope

- **Schema and platform contract:** Schema is **38**; public `Engine.open`
  accepts fresh stores or schema-38 stores only (no public automatic migration).
  Native platform and glibc boundaries are documented in
  [compatibility](../compatibility/index.md).
- **CUDA policy:** Retains the CUDA **12.6** support policy (`cudarc`/Candle
  fork with PTX0 producer policy and F32). CUDA **13** remains explicitly
  deferred out of `0.8.31`.
- **Pre-publication status:** Full source, long-window, paired `0.8.30` vs.
  `0.8.31` latency (`10k`/`50k`/`100k`), GPU/feature-complete, Inspector
  native browser, clean-venv `fathomdb-cli` upgrade, and golden schema-38
  qualification completed in Slice 70; registry publication remains held
  pending Slice 80 authorization.
