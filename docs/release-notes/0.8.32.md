# FathomDB 0.8.32

**Published 2026-11-27.** FathomDB `0.8.32` is live on crates.io (including
`fathomdb-mcp`), PyPI (`fathomdb==0.8.32`, `fathomdb-cli==0.8.32`, and
`fathomdb-mcp==0.8.32`), npm (`fathomdb@0.8.32` on `latest`), GitHub Releases
(with 5-target `fathomdb-mcp` archives and FathomDB Inspector `0.3.0`), and
first-party GitHub Pages (matching `0.8.32+tegra` wheel and Node addon). The
[changelog](https://github.com/fathomadb/fathomdb/blob/release/0.8.32/CHANGELOG.md)
tracks the full change summary, and earlier releases retain their own notes.

## Schema 39 and caller scope isolation

Schema version bumps from **38** to **39** (`S39-COMPOSITE`). Every durable
data-plane table and index carries composite `(scope, ...)` keys backed by a
single-source `fathomdb_schema::TABLE_MANIFEST` (`36` tables, `20`
visibility-trigger tables, and `60` triggers), and `vec0` expands to an
8-column layout carrying `scope TEXT`.

- **Single-scope / single-agent default (`scope = ""`):** By default a FathomDB
  database remains single-scope / single-agent (`ScopePolicy::Unscoped` /
  `ScopePolicy.unscoped()`), so existing single-agent applications require no
  configuration changes.
- **Opt-in multi-scope isolation (`ScopePolicy` / `ScopePredicate`):** Shared
  or multi-agent stores can opt into engine-enforced scope boundaries
  (`single`, `read_only`, and `read_write` policies) across Rust
  (`fathomdb-sdk` and `fathomdb`), Python, and TypeScript. Cross-scope
  violations fail closed with `ScopeViolationError` / `FDB_SCOPE_VIOLATION`.
- **Offline migration (`fathomdb migrate`):** Public `Engine.open` accepts
  fresh stores or Schema 39 stores only with no public automatic migration.
  Committed Schema 38 stores (and chained Schema 37 stores via `37 -> 38 -> 39`)
  upgrade offline with `fathomdb migrate --backup-dir <dir> [--json] <db_path>`
  and pre-upgrade SHA-256 backup verification. See
  [CLI reference](../reference/cli.md).

## Opt-in bulk write mode and Inspector active-scope UI

- **Strict default preserved:** `write` and `actuate` continue enforcing strict
  endpoint integrity on canonical edges.
- **Opt-in bulk / non-strict writes:** `WriteOptions` /
  `EndpointValidationMode::BulkNonStrict` and `write_with_options` /
  `writeWithOptions` across Rust, Python, and TypeScript support out-of-order
  ingestion within the caller's authorized write scope, report exact
  `WriteReceipt.dangling_edge_endpoints` counts, and pair with read-only
  `edge_endpoint_integrity` verification in `fathomdb doctor`.
- **FathomDB Inspector active-`scope` UI:** Inspector `0.3.0` adopts
  `TABLE_MANIFEST`-backed Schema 39 admission and adds an active-`scope`
  switcher and per-view scope filters that stay uncluttered on single-scope
  `""` stores and remain strictly subordinate to `D-01` nondisclosure. See
  [FathomDB Inspector](../inspector/index.md).

## Production read+write `fathomdb-mcp`

`fathomdb-mcp` graduates to a production stdio MCP server with fail-closed
defaults, explicit startup guards, and governed packaging:

- **Read-only default (`allow_writes: false`):** Exposes `7` read-only tools
  (`list_stores`, `use_store`, `orient`, `search`, `fetch`, `expand`,
  `feedback`) with bounded exact frozen-evidence retrieval.
- **Opt-in per-store writes (`9` tools):** Enabling `allow_writes: true` on a
  store requires an explicit non-empty writable `scope` policy and adds
  `actuate` and `put_latest_state` (`ActuationOperationV1::PutLatestState`)
  with strict-only atomic writes, idempotent `(store, scope, operation_id)`
  replay, CAS `expected_write_boundary` preconditions, and `SC-01`–`SC-10`
  startup conflict checks. Operator recovery, erasure, migration, and raw SQL
  remain excluded.
- **Engine & SDK parity primitives:** Adds `read.visibility_state` /
  `read.visibilityState` (`VisibilityStateV1`), `create_if_missing=False` /
  `{ createIfMissing: false }` (`DatabaseNotFoundError` /
  `FDB_DATABASE_NOT_FOUND`), `58` live governed operations (`97` allowlist
  members), and `49` shared error classes (`1` base + `48` leaf). See
  [MCP Server reference](../reference/mcp.md),
  [MCP Server guide](../guides/mcp-server.md), and the
  [SDK operation map](../generated/sdk-operation-map.md).
- **Three-channel packaging:** crates.io publishes `fathomdb-mcp` with
  `default = []` (thin default build); PyPI (`fathomdb-mcp` / `fathomdb[mcp]`)
  and 5-target GitHub Releases package `fathomdb-mcp` compiled with
  `--features default-embedder`.

## Projection lifecycle, pooled-reader caching, and `PerHitExplain.vector_cosine`

- **Empty-DB reopen cursor fix (`owner_kind`):** Adds `owner_kind` on
  `_fathomdb_projection_terminal` so reopening an empty database preserves
  monotonic terminal cursor accounting without colliding across canonical and
  non-canonical owners.
- **Per-class projection namespace (`ProjectionTarget`):** Upgrades
  `_fathomdb_projection_registry` to `PRIMARY KEY(entity_class, name)` so node
  and edge projections carry independent namespaces, and replaces bare string
  drop/delta entries on `configure_projections` and `ProjectionDelta` with
  strictly typed `ProjectionTarget` across Rust, Python, and TypeScript.
- **Cached pooled-reader projection status and `vector_cosine`:** Caches
  projection-generation status across pooled readers on
  `search(..., explain=true)`, `search_frozen(..., explain=true)`,
  `search_with_evidence`, and query-seeded `graph.expand` to eliminate
  steady-state full completion scans, and exposes additive
  `PerHitExplain.vector_cosine: Option<f64>` across Rust, Python, and
  TypeScript.

## Query scale, evidence eligibility, erasure, and frozen-read additive stability

- **Narrowed purge receipt redaction and erasure cursor floors:** Single-node
  `purge(logical_id)` narrows actuation receipt redaction to purged
  entity/revision references so surviving sibling entities sharing a
  `source_id` bucket keep their idempotent receipts (while
  `erase_source(source_id)` continues redacting the entire bucket), alongside
  hardened monotonic cursor floors across all erasure paths. See
  [erasure](../operations/erasure.md).
- **FTS/evidence and `read.get(include_superseded=true)` scaling:** Decouples
  lightweight `EvidenceContributionV1` tracking from `explain = true` when
  `search_with_evidence(include_explanation = false)` and moves
  `read.get` / `read.get_many(include_superseded = true)` onto indexed
  `SEARCH`-only `UNION ALL` lookup, eliminating `O(N)` scans on hot paths.
- **Artifact-scoped evidence `property_predicates`:** Scopes
  `SearchFilter.property_predicates` to the queried artifacts on evidence
  source authorization (`search_with_evidence`, `resolve_evidence`,
  `resolve_evidence_many`, `graph.expand(include_evidence=True)`,
  `resolve_graph_evidence`) while maintaining strict source enforcement for
  access-bearing `attributes`, lifecycle, dependency closures, and
  `ScopePolicy` (and symmetric `trace_dependency`).
- **Schema 39 partitioned frozen-read additive stability:** Adds
  `_fathomdb_scope_visibility_watermarks`, `global_struct_gen` /
  `global_struct_nonce` on `_fathomdb_read_visibility_state`, `ReadSurface`, and
  `0x53 0x39` trailing wire tags on `FrozenReadContextV1` (`492 B` unscoped /
  `556 B` scoped) so disjoint-`kind` additive writes, operational log/state
  writes, disjoint-scope writes, and disjoint-`(scope, kind)` background vector
  commits avoid spurious frozen-read drift while preserving fail-closed
  boundaries, per-slot `resolve_evidence_many` refusal on drifted `Edge` /
  `GraphArm` slots, and `fathomdb-mcp` cold probes (`MR-070.2`). See
  [frozen evidence](../guides/frozen-evidence.md).

## Durability, backup/restore/rebuild, fuzzing, and power-loss verification

- **Declared WAL `SyncMode` (`Normal` / `Full`):** Exposes
  `SyncMode::{Normal, Full}` on `EngineConfig` (`sync_mode` / `syncMode`,
  defaulting to `SyncMode::Normal` for checkpoint-bounded atomic prefix
  recovery with opt-in `SyncMode::Full` for per-commit WAL `fsync`), applied
  uniformly across the primary writer and all projection-worker, runtime,
  dispatcher, and probe connections in Rust (`fathomdb-engine`, `fathomdb`,
  `fathomdb-sdk`), Python, TypeScript, and write-enabled `fathomdb-mcp` stores.
- **Backup, restore, rebuild, and internal `fathomdb.logical-export/v1`:**
  Qualifies installed-artifact operator backup/restore/rebuild
  (`fathomdb doctor safe-export` -> disposable restore -> separate
  `fathomdb recover --accept-data-loss --rebuild-projections` and
  `--rebuild-vec0` -> dense embedder reopen and `drain()` ->
  `fathomdb doctor check-integrity --full` + `data-plane-integrity`, `0`
  findings) alongside a feature-gated internal `fathomdb.logical-export/v1`
  module (`test` / `test-hooks` / `operator`, absent from default public SDK
  APIs) covering all `36` `TABLE_MANIFEST` tables with atomic pending-erasure
  refusal and derived-vector exclusion.
- **Standalone `fuzz/` workspace:** Isolated coverage-guided fuzzing workspace
  (`exclude = ["fuzz"]` in root `Cargo.toml`, zero fuzz dependencies in
  shipping crates) with `7` structured targets reaching `2,185,400` combined
  `ASan` + `UBSan` executions and `0` FathomDB defects, paired with
  deterministic stable `#[test]` regression suites. See
  [contributing](../contributing/index.md#coverage-guided-fuzzing-standalone-fuzz-workspace).
- **QEMU/KVM `dm-flakey` power-loss verification:** Disposable user-mode
  QEMU/KVM `dm-flakey` campaign (`cache=none`, QMP `quit`, two-phase
  `INFLIGHT`/`ACK`/`ERR` virtio-serial oracle, zero host `sudo`) passing
  `11 / 11` live power-loss scenarios across `SyncMode::Normal`,
  `SyncMode::Full`, mid-`INFLIGHT` cuts, mid-erasure recovery, and fail-closed
  `EIO`. See [operations](../operations/index.md).

## Breaking changes

- **Schema 38 -> 39:** `SCHEMA_VERSION` advances to **39**. Public
  `Engine.open` accepts fresh stores or Schema 39 stores only (no public
  automatic migration). Committed Schema 37 and Schema 38 stores must upgrade
  offline with `fathomdb migrate --backup-dir <dir> <db_path>`.
- **Strictly typed `ProjectionTarget` on `configure_projections` and
  `ProjectionDelta`:** Bare string projection names are no longer accepted in
  `configure_projections(..., drop=...)` or returned in `ProjectionDelta`
  (`built`, `dropped`, `deferred`). Callers must pass and consume typed
  `ProjectionTarget` (`name` + `entity_class` / `entityClass`); passing bare
  strings raises `TypeError` in Python and TypeScript and fails to compile in
  Rust.
